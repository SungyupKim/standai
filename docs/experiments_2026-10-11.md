# 서기·일어서기 조사 기록 (2026-10-11)

stand-only 트랙에서 "왜 harsh(쓰러진 시작)가 안 풀리는가"를 하루 동안 파고든 기록이다. 결론을
먼저 쓰고, 근거 수치와 실패·실수를 그대로 남긴다. 재현 스크립트는 `scripts/analysis/`
(사용법은 그곳의 README), 운영 명령은 `CLAUDE.md`.

## 0. 성과 요약 (2026-10-11 기준)

올바른 대조군은 **v21 82.425M을 같은 1.5배 몸에서 잰 값**이다(v30의 출발점). v28의 시작점으로 쓴 v26은
replay 커리큘럼 학습 때문에 이 대조군보다 낮아서, 처음 v26 대비로 보고한 이득은 과장이었다(7절).

| 지표 (결정론적 정책, 고정 시드, **기어 1.5배 몸**) | v21 대조군 | v28 (최고 시점) |
|---|---|---|
| 게이트 calm / full / harsh (시드 100개) | 43 / 24 / 5 | 47~54 / 23~29 / 6~9 |
| calm 전체 (시드 300개) | 136/300 (45%) | 152~154/300 (51%) |
| 정자세 시작(무릎 -10° 이상) 성공 | 77% | 84~85% |
| harsh: 0.7m 아래 시작해 진짜 직립 | 6/197 (전부 시작 0.6~0.7m) | 6~8/197 (전부 시작 0.62~0.67m) |
| harsh: 시작 0.6m 미만에서 직립 | 0/160 | 0/160 |

- **확실한 성과:** 몸을 1.5배로 키우면 calm이 오른다(1배 몸에서 v21 gate calm 33, 1.5배 몸에서 43). v28의
  추가 학습은 그 위에 작은 이득(300시드 +16~18, 게이트 +4~11)이다.
- **풀리지 않은 것:** 바닥에서 일어서기. 대조군도 v28도 시작 0.6m 미만에서 직립으로 끝난 경우가 0이다. 6~8/197은
  임계값(0.7m) 바로 아래에서 시작하는 거의 선 자세의 복구로, 학습으로 얻은 능력이 아니라 출발 체크포인트가 이미
  하던 것이다.
- **몸 사양을 기어 1.5배로 바꿨다**(8절). 따라서 v28 이전 수치와 직접 비교하지 않는다.

## 0-1. 한 문단 요약

- calm(거의 선 자세 시작)의 3초 생존은 30~40/100, harsh-only는 4~7/100에서 v21→v26까지
  수십M 스텝 동안 움직이지 않았다. harsh가 낮은 건 **바닥에서 정책이 거의 일어서지 못하기 때문**이다
  (0.7m 아래에서 시작한 harsh 197개 중 5초 안에 선 것 1개).
- 몸이 못 해서가 아니다. 정확한 시뮬레이터로 앞을 내다보는 MPC(진단용 오라클)는 같은 몸으로 누운
  시작에서 일어선다. 그리고 **토크 여유가 얇다**: 기어 1배에서 6개 시작 중 2개, **1.5배에서 5개**,
  2배에서 5개가 선다. 다만 한 관절 그룹만 키워서는 이 효과가 재현되지 않았다(3.5절).
- 보상 성형(`ground_shaping`, `getup_reward`)과 실패 시작 재생(`replay_curriculum`)은 효과가 없었다.
  몸 사양(기어 1.5배)을 바꾼 v28에서 calm이 크게 올랐고, harsh는 지켜보는 중이다.
- 이 과정에서 측정 함정과 우리 쪽 실수가 여럿 나왔다(7절, 대조군을 잘못 고른 것 포함). 방법론적 교훈이 결과만큼 가치 있다.

## 1. 측정 원칙

- 학습 로그 지표(`fall_rate`, `ep_len_mean`, `value_loss`)는 확률적 행동 기준이라 결정론적 게이트와
  어긋난다. **모든 수치는 결정론적 정책, 고정 시드, 원래 몸(기어 1배)** 기준이다.
- 게이트: 시드 0..N-1로 리셋, 150스텝(3초) 동안 몸통 높이가 `FALL_HEIGHT=0.7m` 밑으로 한 번도 안
  내려가면 성공. calm / full(기본 혼합) / harsh-only(`set_calm_frac(0)`).
- **시드 100개의 표본 오차는 ±4~5%p**라서 harsh 4와 7은 구분되지 않는다. 구간별 표는 시드 300개를
  쓰되 구간당 n=25~79라 ±6~10%p. 같은 시드끼리 비교하면 쌍(paired) 효과로 조금 더 믿을 만하다.
- 환경은 몸통이 `FALL_HEIGHT` 밑인 상태가 250스텝(5초) 이어지면 에피소드를 끊는다
  (`DOWN_RECOVERY_STEPS`). 즉 "더 오래 기다려 주면 일어선다"는 가설은 환경 규칙상 5초가 상한이다.
  (바닥 정책 `FloorEnv`는 2026-10-14부터 `down_timeout=False`로 이 규칙을 끌 수 있고, 3.17절의 바닥 정책 수치는 끈 상태다.)

## 3. 핵심 발견

### 3.1 harsh는 "바닥에서 못 일어섬"이다 (측정 방식 때문이 아니다)
v23 112M, harsh 시작 300개: 0.7m 밑에서 시작 197개 중 5초 안에 선 것 **1개**, 높이 증가 중앙값 0.06m,
46%는 0.05m도 못 올랐다. 처음엔 "게이트가 시작 높이 때문에 회복을 가린다"고 의심했으나, 회복 기준으로
다시 재도 28/300 vs 게이트 26/300으로 같았다(가설 기각). 정책은 가만히 있는 게 아니라 움직이는데
(행동 변동 0.59 > 서 있을 때 0.52) 올라가지 못한다.

### 3.2 calm도 균일하게 풀린 게 아니다
calm 시작에도 가벼운 교란(`severity`≤0.3)이 들어가 상당수가 웅크린 채 시작한다. v23 98.9M, 시드 300개:

| 초기 무릎 굽힘 | 성공 |
|---|---|
| -10° 이상 | 82% (61/74) |
| -25°~-10° | 54% |
| -40°~-25° | 28% |
| -60°~-40° | 19% |
| -60° 미만 | 0~3% |

### 3.3 보상에 골짜기가 있었다
harsh 시작에서 몸통 높이 구간별 스텝당 평균 보상(v23 정책): 완전히 누운 자세(<0.2m) 2.58 > 조금 올라간
자세(0.2~0.35m) 1.96. 차이의 대부분은 `com`(0.82 vs 0.28). 즉 올라가려는 시도가 손해였다.
`knee_avoid`는 무릎 높이를 보는 항이라 웅크려 다리를 세운 자세(일어서기에 필요)가 보상받으므로
**게이트하지 않았다**. `ground_shaping`/`getup_reward`로 골짜기는 없앴지만(총 보상이 높이에 대해 단조
증가) 바닥 근처 기울기는 여전히 작고(1.36→1.55→1.94), 36M 스텝 학습에서도 harsh는 안 움직였다.

### 3.4 `recovery_gate`는 성능에 영향이 없다 (되돌릴 이유 없음)
v22(게이트 없음)와 v23(있음)는 같은 체크포인트에서 같은 harsh 혼합으로 갈라졌고 게이트가 같았다
(harsh 4–7 vs 5–7). 낮은 구간에서 knee_straight가 누운 자세를 보상하던 문제(펴짐 2.188 > 굽힘 1.785)를
없앤 설계는 Tao 외(2022)도 같은 방향(직립 보상은 COM 높이 0.5m 이상에서만)이다.

### 3.5 몸은 일어설 수 있다 — 그리고 토크 여유가 얇다
오픈루프 CEM(경로 전체를 한 번에 최적화)은 목적함수를 네 번 바꿔도 못 섰다.
v1(몸통 높이만): 물구나무·공중 이탈로 높이를 얻음 / v2: 같은 편법 / v3(직립 요구): 앉은 높이(0.3m대)에서
정체, 시드 8만 서기 직전 / v4(중간 직립 곱 제거, 발 접촉 조건): 0/6, 시드 8조차 후퇴.
**닫힌 루프 MPC**(예측 샘플링, 매 스텝 0.5초 앞을 128개 후보로 시험, 정확한 시뮬레이터)는 섰다.
시작: 시드 8, 16, 22, 3, 7, 11 (시작 높이 0.10~0.36m).

| 기어 배율 | 선 시작 | 처음 선 시점 |
|---|---|---|
| 1.0배 | **2/6** (시드 8, 7) | 72~81스텝 (1.4~1.6초) |
| 1.5배 | **5/6** (시드 8은 90%, 16·22·3·11은 100%) | 30~73스텝 |
| 2.0배 | **5/6** (7만 실패) | 22~39스텝 (0.4~0.8초) |

(2배는 재실행에서 동일하게 재현. "선다"는 마지막 50스텝의 서 있음 비율로 판단하고, 열린 루프 재생은
접촉 때문에 어긋날 수 있어 보수적이다. n=6이라 비율의 불확실성이 크다.) 기어 1배는 임계점 바로 아래로 보인다.

같은 방향의 정책 쪽 증거: v26 정책(91.0M)을 기어만 키운 몸에서 재면(시드 300개) 웅크린 구간이 오른다.

| 기어 | 전체 | -60°~-40° | -40°~-25° | -10° 이상 |
|---|---|---|---|---|
| 1.0배 | 115/300 | 17% | 28% | 74% |
| 1.5배 | 140/300 | 36% | 48% | 74% |
| 2.0배 | 123/300 | 36% | 52% | 55% |
| 3.0배 | 62/300 | 19% | 24% | 27% |

2배 이상에서 정자세가 무너지는 건 몸이 강해서가 아니라 1배 몸에 맞춰 학습된 정책의 불일치(추정,
미확인)로 보인다.

**관절별 MPC 스윕** (기본 1배 몸에서 해당 관절만 1.5배, 같은 시작 6개, 선 개수는 마지막 50스텝 80% 이상):

| 조건 | 선 시작 | 서 있음 비율 (시드 8 / 16 / 22 / 3 / 7 / 11) |
|---|---|---|
| 전부 1배 | 2/6 | 시드 8, 7 |
| **전부 1.5배** | **5/6** | 시드 8, 16, 22, 3, 11 |
| 무릎만 | 2/6 | 100% / 0 / 0 / 80% / 0 / 0 |
| 엉덩이만 | 1/6 | 98% / 0 / 0 / 30% / 0 / 60% |
| 엉덩이+무릎 | 2~3/6 | 100% / 98% / 14% / 76% / 0 / 0 |
| 발목만 | 1/6 | 80% / 0 / 0 / 22% / 0 / 0 |

어떤 단일 관절 그룹도 "전부 1.5배"(5/6)에 근접하지 못했다. 이 샘플링 MPC는 설정이 조금만 바뀌어도 시드 단위로
결과가 달라져서(예: 시드 7은 1배에서는 98%로 섰는데 위 조건들에서는 모두 실패) n=6으로는 한두 개 차이를
읽을 수 없다. **허리와 팔은 시험하지 못했고**, "전부 1.5배"의 효과가 팔로 바닥을 밀거나 허리로 상체를
일으키는 동작에서 왔을 가능성은 추측일 뿐이다. 따라서 "무릎이 병목"이라는 해석은 지지되지 않는다.

### 3.6 효과가 없었던 것 (부정적 결과)
- `getup_reward` 36M 스텝: 게이트 변화 없음, harsh 시작에서 끝에 선 것 0/197, 높이 증가 중앙값
  0.06→0.04m. `getup_shift` 항은 7.8→0.5로 오히려 줄었다(원인 미확인).
- `replay_curriculum` 9M 스텝: 같은 시드 300개로 출발점(117/300)과 같은 수준(117/300). 웅크린 구간
  -40°~-25°: 30% → 20%(84.8M) → 32%(90.6M). 재생 풀은 커졌고(32→2,000개) 재생 성공률 지표도 올랐지만
  버킷 구성이 바뀌는 지표라 정책 개선과 구분되지 않는다.

| -10° 이상 | 65% | **85%** |
| 전체 | 123/300 | **152/300** |

harsh 시작 300개 진단은 변화가 없다: 0.7m 아래에서 시작한 197개 중 끝에 선 것 5개(출발점도 5개),
높이 증가 중앙값 0.07→0.06m. 1배 몸에서는 이 값이 0~1개였으므로 강한 몸에서는 바닥에서 일어서는 시도가
조금 있지만, v28 학습으로 늘지는 않았다. **판단 기준:** 약 10M 스텝 시점에서 harsh 게이트와 이 진단이
오르는지.

### 3.8 누운 자세에서는 일어서지 못한다 — 정정과 `knee_avoid` 게이트 (v29)

**정정:** 3.7절 끝에서 "강한 몸에서는 바닥에서 일어서는 시도가 조금 있다 / harsh 5→9로 싹이 보인다"고 적었으나
과한 해석이었다. v28(105.7M)에서 0.7m 아래로 시작한 harsh 197개의 시작 높이별 진짜 직립 종료:

| 시작 몸통 높이 | n | 직립으로 끝남 |
|---|---|---|
| 0.00~0.15m | 36 | 0 |
| 0.15~0.30m | 49 | 0 |
| 0.30~0.45m | 41 | 0 |
| 0.45~0.60m | 34 | 0 |
| 0.60~0.70m | 37 | 8 (시작 0.62~0.67m) |

증가분은 임계값 바로 아래의 약간 무너진 자세를 복구하는 능력이고, **바닥에서 일어서는 문제는 풀리지 않았다.**

**관찰(뷰어)과 수치:** 쓰러져 있을 때 정책이 손으로 밀기보다 다리를 높이 들어 반동으로 일어나려 한다.
몸통이 낮은 구간(z<0.5m, 189개 에피소드): 무릎 높이 평균 0.30m·최대 0.58m, 엉덩이 흔드는 속도 2.7 rad/s,
에피소드당 몸통 1.4바퀴 회전(v23 1.1, v26 1.4 -- 구르기 자체는 예전부터 있었고 v28에서 새로 생긴 게 아니다),
뒤집힌 시간 비율 11%→16%. 바닥 접촉: 팔 43%, 머리 31%, 발 27%, 몸통 12% (팔이 닿는 것이 밀기인지 깔고
구르는 것인지는 구분하지 못함). 이 구르기에서 얻은 높이는 편법이 아니었다: 높이 기준을 넘긴 에피소드와 진짜
직립 에피소드의 수가 같았다(v28: 6/197 vs 6/197).

**가설(미검증):** `knee_avoid`가 무릎이 높을수록 보상하므로(누워서 다리를 든 구간 0.34~0.89/step) 일어서기가
아니라 다리 흔들기를 보상하고 있다. 이전에 이 항을 "웅크린 다리가 일어서기에 필요하다"며 게이트하지 않았던
판단(3.3절)을 재검토한 것이다.

**v29:** `--knee-gate`: `knee_avoid`를 머리 높이로 감쇠(0.5m 이하 0, 0.9m 이상 전부, 사이는 선형). 몸통이 낮은
구간에서 보상이 0.34~0.89 → 0.00~0.01로 꺼졌고 서 있는 구간(0.99)은 그대로, calm 시작(머리 0.9m 이상)은 영향이
없다. **판단 기준:** 0.6m 미만에서 시작한 harsh에서 직립으로 끝나는 에피소드가 0을 벗어나는지, 구르기 횟수가
줄어드는지, calm·정자세(-10° 이상 ~85%)가 유지되는지. 머리 접촉·뒤집힘 벌점은 아직 켜지 않았다
(`--getup-reward` 묶음에만 있음).

### 3.9 v30: calm에서 다시 시작 + 머리 높이 상승 보상

harsh를 섞으며 굳은 구르기·다리 반동 습관을 물려받지 않도록 harsh 도입 전 calm 체크포인트(v21 82.425M)에서
다시 시작한다(연쇄 warm start 1회). 보상 추가는 두 가지, 동시에 얹는다: `--knee-gate`(3.8절)와
`--head-progress K=300`.

`head_progress` = `K * (γ·φ(다음) - φ(지금))`, φ는 머리 높이를 0.9m에서 자르고 0~1로 정규화한 값, γ=0.99(PPO γ와
일치 확인). **포텐셜 기반이라 할인 합이 `K*(γᵀφ_끝 - φ_시작)`으로 정확히 상쇄되고(구현 오차 2e-13) 최적 정책을
바꾸지 않는다.** 하는 일은 올라가는 순간순간에 즉시 보상을 주어 GAE(약 17스텝 시야)가 바닥 근처의 약한 상승을
알아보게 하는 것이다. 앉아서 점수를 받아먹거나 오르내리며 보상을 쌓는 것은 불가능하다. 로그의
`r_head_progress`는 크고 음수(서 있을 때 스텝당 `(γ-1)*K*φ` ≈ -3)로 보이는 것이 정상이며 가치 함수가 흡수한다.
K=300에서 머리가 0.2→0.9m로 완전히 오르면 약 +230을 한 번에 받는다.

**한계:** 이 보상은 탐색을 돕지 못한다. 정책이 한 번도 안 한 동작은 여전히 안 나온다. 이전의 `ground_shaping`(높이에
선형 점수, 1배 몸 36M 스텝)이 효과가 없었던 것과 같은 종류의 실패가 반복될 수 있다. 또 두 변경을 동시에 얹은
재시작이라 효과가 있어도 어느 쪽 덕인지는 대조군(v21을 1.5배 몸에서 두 보상 없이 시작)이 있어야 분리된다.

### 3.10 탐색 진단과 머리 높이 신기록 보너스 (v31)

**calm에서 굳은 습관이다:** harsh를 한 번도 겪지 않은 v21(60M, 82.4M)도 쓰러진 자세에서 이미 다리를 들고
엉덩이를 휘두르며(3.4 rad/s) 1.5바퀴 구른다(무릎 최고 높이 0.5m대). 서 있을 때의 균형 반사가 낯선 자세에서
그대로 나오는 것이다. v28은 이 습관이 오히려 강해졌고(무릎 평균 0.25→0.33m, `knee_avoid` 0.40→0.58/step),
v30(`knee-gate`)은 v21 수준 이하로 줄었다(엉덩이 속도 2.0, 회전 0.98바퀴). 구르기가 줄어든 자리에 일어서기는 나오지
않았다.

**`head-progress`는 "파격적"이 아니었다:** 포텐셜 기반이라 올라갔다 내려오면 상쇄되고 최적 정책을 바꾸지 않는다.
K를 키워도 구조는 같다. 높이를 유지하지 못하는 정책에게는 순이득이 거의 없다.

**탐색 진단**(`scripts/analysis/explore_probe.py`, v30, 몸통 0.45m 미만 시작 126개, 250스텝):

| 행동 노이즈 | 머리가 0.5m 넘음 | 0.9m 넘음 | 직립 종료 | 최고 머리 높이 중앙값 |
|---|---|---|---|---|
| 없음 | 4% | 0% | 0 | 0.28m |
| 학습 때와 같음(×1, 백색) | 4% | 0% | 0 | 0.26m |
| ×2 백색 | 4% | 0% | 0 | 0.26m |
| ×3 백색 | 6% | 0% | 0 | 0.29m |
| ×1 상관(ρ=.9) | 6% | 0% | 0 | 0.28m |
| ×2 상관(ρ=.9) | 10% | 0% | 0 | 0.33m |
| ×3 상관(ρ=.95) | 10% | 0% | 0 | 0.36m |

정책 행동 표준편차는 이미 평균 0.52(상한 0.6 근처)라 백색 노이즈를 더 키워도 소용이 없다. 스텝마다 독립인 노이즈는
몸의 반응에서 상쇄된다. **시간적으로 이어지는 노이즈만 머리를 더 높이 올린다.** 그래도 0.9m나 직립은 어떤 설정에서도
0이다. 해결책 후보는 gSDE(정책 구조가 바뀌어 처음부터 학습해야 함)와 행동 유지(sticky action) 래퍼(미구현).

**v31 `--head-record K=400`:** 그 에피소드에서 머리가 도달한 최고 높이(0.9m에서 자른 정규화 값)를 갱신할 때만
`K * (새 최고 - 이전 최고)`를 준다. 발이 바닥에 닿아 있을 때만 인정(도약·다리 휘두르기 무효화). 내려와도 회수되지 않고
같은 높이는 한 번만 지급되어 반복 획득이 불가능하다(에피소드 상한 ≈ `K*(1-시작 높이)` ≈ 320). calm 시작은 머리가 이미
상한이라 0. 검증: 무작위 휘젓기 평균 +31(최대 112), v30 정책 평균 +28(최대 143, 바닥 에피소드의 84%가 지급), calm 0.00,
상한 위반 없음. **한계:** 낮은 단계의 보상은 무작위 행동도 쉽게 얻으므로 정책을 가르는 것은 얼마나 더 높이 올라가는가이고,
탐색 자체를 만들지는 못한다. 위 탐색 진단이 보여 주듯 이어지는 노이즈가 병행되지 않으면 0.9m에 닿기 어려울 수 있다.

### 3.11 이어지는 탐색 노이즈 (v32)

3.10의 탐색 진단은 "노이즈를 키우는 것"이 아니라 "노이즈를 시간적으로 이어 주는 것"이 머리를 더 높이 올린다는 것을
보였다. PPO는 기본적으로 매 스텝 독립인 노이즈로 행동을 뽑는데, 몸이 토크를 저역통과하므로 스텝마다 독립인 흔들림은
상쇄된다. gSDE는 정책 구조가 바뀌어 처음부터 학습해야 해서, 체크포인트를 유지하면서 쓸 수 있는
`ColoredNoiseCallback`을 만들었다: 롤아웃의 `policy.forward`만 교체해 행동을 `평균 + 스케일 * 표준편차 * eps_t`로
뽑고 `eps_t`는 정상(stationary) AR(1)(`eps_t = ρ eps_{t-1} + sqrt(1-ρ²) N(0,1)`)이다. 스텝별 주변분포는 정책 자신의
가우시안과 같고(저장되는 log-prob도 정책의 것), 스텝 간 상관만 생긴다. 몸통이 0.5m 아래인 환경에서만 노이즈를 추가로
1.5배 키워(`--floor-noise-scale`) calm 균형 학습은 건드리지 않는다.

단위 검증(v31 정책, 환경 4개 3000스텝): 적용된 노이즈 / 정책 표준편차 = 1.00(기대 1.0), 바닥에서 1.49(기대 1.5), lag-1
자기상관 0.90(기대 0.90), log-prob 유한, 결정론 경로·평가 경로 영향 없음, 학습 종료 시 원래 함수로 복원.

**한계/편향:** (1) 노이즈가 상관되어 있어 "상태가 주어졌을 때의 행동 분포가 정책과 같다"는 PPO의 가정이 정확히는
깨진다(과거 노이즈가 상태에 반영됨). 색 노이즈 탐색 연구들이 쓰는 근사이지만 이론적으로 편향이 있다. (2) 바닥 1.5배는
샘플링 분포가 정책보다 넓어지는 작은 off-policy 편향이다(PPO 클리핑이 어느 정도 흡수). (3) 이것도 탐색을 돕는
장치일 뿐, 0.9m 이상 도달이나 직립은 어떤 노이즈 설정에서도 아직 0이었다(3.10절).

### 3.12 정책 없는 탐색이 정책보다 높이 올린다 — 바닥 버스트 (v34)

**동기:** "노이즈를 키워도 다 다리만 든다"는 관찰. 지금까지의 노이즈 실험은 전부 정책의 평균 행동 주변에 더한 것이라
정책이 하는 동작(다리 들기)에 매여 있다. 정책 없이 순수하게 무작위로 움직이는 경우(`random_explore.py`, 바닥 시작
126개, 몸통 0.45m 미만, 250스텝):

| 행동 출처 | 머리 0.5m↑ | 0.9m↑ | 직립 | 최고 머리 중앙값 |
|---|---|---|---|---|
| 현재 정책(결정론, v32) | 6% | 0% | 0 | 0.28m |
| 무작위 AR(1) 표준편차 0.5, ρ=0.9 | 6% | 1% | 0 | 0.34m |
| 무작위 AR(1) 표준편차 1.0, ρ=0.9 | 21% | 2% | 0 | 0.40m |
| 무작위 AR(1) 표준편차 2.0, ρ=0.95 | 31% | 2% | 0 | 0.44m |
| **무작위 ±1을 10스텝 유지** | **77%** | **11%** | **1** | **0.59m** |
| 무작위 ±1을 25스텝 유지 | 52% | 6% | 1 | 0.51m |
| 무작위 ±1을 50스텝 유지 | 29% | 3% | 0 | 0.42m |

**학습된 정책은 바닥에서 머리를 올리는 데 무작위 bang-bang보다 못하다.** 필요한 탐색은 크기 증가가 아니라
"정책에 매이지 않고 / 큰 진폭으로 / 약 0.2초 유지되는" 것이다.

**v33 실패(교훈):** 버스트 행동(±1)을 정책의 행동으로 버퍼에 저장했더니 첫 업데이트부터 `approx_kl` 2.4e6,
`clip_fraction` 0.93, 표준편차 0.52→0.33으로 폭주하다 NaN으로 크래시했다. ±1 패턴은 정책 가우시안의 꼬리 깊숙한
곳이라 PPO 중요도 비율이 폭발한다. **정책 분포 밖의 행동을 PPO 버퍼에 넣으면 안 된다.**

**v34 설계:** 버스트를 **환경의 외란**으로 처리한다. 롤아웃에서 정책은 자기 분포에서 뽑은 행동을 평소처럼 저장하고(on-policy),
바닥의 환경(몸통 0.5m 미만)에는 확률적으로(스텝당 0.1, 대기 중일 때) 무작위 ±1 패턴을 10스텝 동안 `step_async`에서 대신
실행한다. 버스트 구간에서 저장된 행동과 결과는 무관해 평균 기울기 기여는 0이고(분산만 증가), 버스트로 머리가 올라간 자세에서
이어지는 정책 행동에는 정상적으로 보상(`head-record` 등)이 연결된다. 바닥 시간의 약 절반이 버스트다.
시작 직후 건강한 값: approx_kl 0.04~0.05, std 0.51, 에피소드당 `r_head_record` 7→28~34.

**부작용 발견(v32):** 바닥 노이즈 1.5배는 정책보다 넓은 off-policy 샘플이라 정책이 그 행동을 피하도록(표준편차를
줄이도록) 학습된다(0.50→0.46, v33에서 0.345). v34는 이를 1.0배로 되돌렸다.

**주의:** 게이트·진단은 버스트 없이 정책 자체를 잰다. 버스트로 높이 올라간 자세는 학습 신호일 뿐 성과 지표가 아니다.

### 3.13 v34 결과와 "정책에 남기기" (v35)

**v34(6.7M 스텝) 결과:** 학습 중 머리 신기록 보상은 7→25~34로 올랐지만(버스트가 높은 자세를 만든다), 정책 혼자(버스트·노이즈 없이)
바닥 시작 126개: 머리 0.5m↑ 5%→7%, 0.9m↑ 0%, 직립 0/126, 최고 머리 중앙값 0.28m로 **변하지 않았다.** calm은 유지
(게이트 43~54, 300시드 150/300, 정자세 시작 82%). 걱정되는 변화 셋: 정책 표준편차 0.51→0.32 감소, 구르기 증가(1.42바퀴,
뒤집힌 시간 17%), `value_loss` 약 2배. 버스트는 PPO 버퍼에 들어가지 않으므로 그 동작이 정책 자체에 남지 않는다.

**"남기는" 세 방법을 검토했다.** (1) 성공한 버스트의 자기 모방: 버스트 행동은 무작위 패턴이라 같은 상태에서 성공하는 패턴이 여럿이면
가우시안 정책이 그 평균(≈0)을 배울 위험이 있어 보류. (2) 버스트가 도달한 높은 자세를 시작점으로 재사용(보관소). (3) 정책 자신의
탐색 폭(표준편차 하한·엔트로피). v35는 (2)와 (3)을 쓴다.

**v35 구성**
- `--burst-archive-frac 0.25`: 환경이 바닥 시작 에피소드에서 머리 0.45~0.90m, 발 접촉, 몸통 뒤집히지 않음(|pitch|<70°) 조건을
  만족하는 상태를 최대 10스텝에 하나씩 `info["archive_state"]`로 보고하고, 콜백이 4개 높이 구간(0.45/0.55/0.65/0.75/0.90m)에
  나눠 보관한다. 5만 스텝마다 구간별 균등 비중(적은 구간은 복원 추출)으로 풀을 만들어 모든 리셋의 25%를 그 자세에서 시작시킨다
  (`set_replay_pool` 재사용). 순수 RL(리셋 분포만 바뀌고 off-policy 행동 없음)이고, "올라온 뒤"를 연습하게 한다.
  보관소에서 시작하면 `head_best`가 그 높이로 초기화되어 `head-record`는 새 최고만 보상한다.
- `--std-min 0.45`: 시작 시 평균 표준편차 0.315→0.450으로 올리고 이후 하한으로 유지. `--ent-coef 0.002`는 보조.

**단위·시험 검증:** 무작위 버스트로 바닥 시작 60개에서 보관소 상태 61개(높이 범위 맞음, 낮은 구간 쏠림 32/13/9/7), 서 있는 시작에서는 0개,
보관소 자세에서 리셋하면 그 높이에서 시작함을 확인. 실제 학습 루프 시험에서 크래시 없이 표준편차 0.45 유지, approx_kl 0.06.

**한계:** (1) 보관소 자세(앉기·무릎 꿇기 높이)에서 이어 서는 것도 정책은 아직 한 번도 못 했다(0.3~0.6m 시작 직립 0/75). 보관소는 그
연습량과 현실적인 자세를 줄 뿐 동작을 발견해 주지는 않는다. (2) 무작위 버스트로 직립까지 간 것은 126개 중 1개라서, 보관소의
높은 쪽 구간은 얇다. (3) 워밍 스타트 연쇄가 v21→v30→v31→v34→v35로 4회이고 5회 이상이면 불안정해질 수 있다는 경고가 있다.

### 3.14 v36: calm 체크포인트에서 다시 시작 (연쇄 초기화)

v34→v35까지 워밍 스타트 연쇄가 4회(v21→v30→v31→v34→v35)였고 v32~v35에서 표준편차 감소·구르기 증가가 누적됐다. 이를 끊기 위해
같은 플래그 세트(`knee-gate`, `head-record 400`, 이어지는 노이즈 1.0배, 바닥 버스트, 보관소 25%, 표준편차 하한 0.45, ent_coef 0.002)로
**calm만 학습된 v21 82.425M에서 다시 시작**했다(연쇄 1회).

**`calm_frac`을 1.0에서 서서히 내리지 않고 처음부터 0.5로 둔 이유:** 버스트·머리 신기록 보너스·보관소는 모두 *바닥 에피소드*가 있어야
작동한다. `calm_frac=1.0`에서 시작하면 초반에는 머리를 드는 케이스가 거의 나오지 않고 보관소도 늦게 찬다(서 있는 시작은 보관소에
기여하지 않음). 0.5로 시작하면 몇 분 안에 에피소드당 `r_head_record`가 29~33이 된다. v21은 calm 실력이 이미 충분하다(1.5배 몸에서 43).

**주의:** v21도 쓰러진 자세에서 다리를 휘두르고 1.5바퀴 구르는 반사를 이미 가지고 있다(3.10절). 따라서 이 재시작은 그 습관을
없애는 것이 아니라 v32~v35에서 누적된 표준편차 하락·구르기 증가·연쇄 길이를 되돌리는 것이다. 판단 지표는 정책 혼자(버스트 없이) 값이고,
calm의 대조군은 v21 @1.5배 몸(게이트 43/24/5, 300시드 136)이다.

### 3.15 연계가 끊기는 곳과 프런티어 사다리 (v37)

**진단(`scripts/analysis/chain_probe.py`, v36 정책, 무작위 버스트로 모은 중간 높이 상태 123개, 5초):**

| 시작 머리 높이 | 정책 혼자: 0.9m↑ / 직립 종료 | 무작위 버스트: 0.9m↑ / 직립 | 정책+노이즈 |
|---|---|---|---|
| 0.45~0.60m (68) | 6% / 1 | **15%** / 1 | 4% / 0 |
| 0.60~0.75m (28) | 32% / 2 | 29% / 0 | 21% / 0 |
| 0.75~0.90m (27) | 30% / 0 | 33% / 0 | 30% / 0 |

머리가 0.9m를 넘은 19개 에피소드 중 5초 뒤 직립 3, 서 있는 높이인데 기울어짐 0, **다시 쓰러짐 16**. 머리가 0.9m를 넘은 뒤 몸통이
0.7m 위에 머문 시간은 중앙값 0.56초(상위 10% 2.19초)이고 게이트는 3초를 요구한다. → "굳어서 못 바꾼다"가 아니라 **일어선 직후의 균형
(움직이는 중, 기울어진 상태)이 가장 약한 고리**이고, 가장 낮은 구간(0.45~0.6m)에서는 정책이 무작위 버스트보다 못하다.

**v36 보관소의 빈칸:** 상태를 머리 0.45m 이상만 저장해서 바닥(머리 0.15~0.45m)에서 첫 단계로 올라가는 구간에 사다리 칸이 없었고, 정책이 올라간
상태는 (바닥에서 시작한 에피소드만 기여하므로) 보관소에 추가되지 않았다.

**v37 변경:** (1) 범위 0.25~1.10m, 7칸(0.25/0.35/0.45/0.55/0.65/0.75/0.90/1.10). 맨 아래 칸은 머리가 바닥에서 막 떨어진 누운 자세, 맨 위
칸은 "막 일어선, 아직 움직이는 상태"(위에서 16/19가 쓰러진 바로 그 구간). (2) 프런티어 규칙(Go-Explore 방식): 그 에피소드가 시작한 머리 높이보다
0.08m 이상 올라간 상태만 저장하고, 보관소에서 시작한 에피소드도 기여한다. 각 칸이 다음 칸의 시작점이 되어 연쇄가 쌓인다. 버스트는 여전히 몸통
0.5m 미만에서만 작동하므로 위쪽 칸은 정책 혼자 연습한다. 검증: 1라운드(바닥 시작) 상태 79개(0.26~0.90m, 전부 시작 +0.08m 이상), 2라운드(1라운드
상태에서 시작) 63개로 자기 시작보다 평균 +0.18m 위, 최고 0.95m, 서 있는 시작은 0개.

**누웠을 때 머리 들기에 대해:** 이 구간은 (a) 버스트(바닥 시작의 77%가 머리 0.5m↑)와 머리 신기록 보상이 높이를 만들고, (b) 이제 맨 아래 칸들이 그
자세에서 한 칸 올라가는 것을 정책이 연습하게 한다. 정책 혼자 바닥에서 첫 단계를 올라가는 능력(현재 0.5m↑ 4~8%)이 실제로 오르는지는 아직 모른다.
이 단계의 정책이 무작위 버스트보다 못하다는 점(6% 대 15%)은 해결되지 않은 부분이다.

### 3.16 일어나기 전용 정책 분리 (2026-10-12)

**동기.** 단일 정책은 어떤 체크포인트에서도 0.6 m 미만 harsh 시작을 끝까지 직립으로 끝낸 적이 없다(0/160). 바닥에서의
행동은 calm에서 굳은 다리 휘두르기 반사이고, 정책 단독 머리 0.5 m↑ 비율이 4~8 %로 무작위 버스트(77 %)보다 낮았다.
습관이 없는 새 네트워크를 바닥 시작만 나오는 환경(`FloorEnv`)에서 처음부터 학습한다.

**환경.** 시작 몸통 < 0.5 m, 최대 250 스텝. 보상은 머리 신기록(K=10, 발 닿음) + 작은 머리/몸통 높이 항 + 성공 보너스뿐
(부모 환경의 안정성·자세·jerk 항은 모두 제거). 진동으로 벌 수 있는 항은 없지만 움직임 벌점도 없다.

**결과 (정책 단독, 결정적 행동, 시드 50개).**

| 실행 | 스텝 | 머리>0.5 m | 머리>0.8 m | 성공(느슨한 정의) |
|---|---|---|---|---|
| v1 (버스트) | 1.32 M | 20 % | 0 % | 0 % |
| v2 (버스트 없음) | 0.63 M | 72 % | 4 % | 2 % |
| v2 | 2.80 M | 86 % | 16 % | 12 % |

버스트는 새 정책 학습에서 오히려 방해였다(버스트 구간에서 환경이 행동을 덮어써 학습 신호가 없고, 로그 지표만 부풀림).

**성공 정의의 오류와 교정.** v2의 성공(머리 ≥ 0.9 m + 발 닿음, 순간 조건)을 뷰어에서 성공 후 3초 더 돌려 보니 네 번 모두
몸통 0.31~0.54 m로 주저앉았다 -- 튀어 올랐다 떨어지는 동작이지 서는 자세가 아니었다. 그래서 v3에서 성공을 "몸통 ≥ 0.6 m,
머리 ≥ 0.9 m, 발 닿음, 기울기 < 40°를 20 스텝(0.4 s) 연속 유지"로 바꾸고 몸통 높이 항을 추가했다(v2 @3.35 M에서 이어받음).
**위 표의 v2 성공 12 %는 이 의미로 읽어야 한다(서 있기 성공이 아니다).**

**v3 중간 상태 (4.9 M, 정책 단독 50개).** 성공 0/50, 몸통 최고 > 0.7 m가 12개, 머리 최고 > 0.9 m가 3개, 가장 길게 유지한 스텝 3/20.
approx_kl 0.30~0.34, clip_fraction 0.73~0.75, std 0.60 이상으로 업데이트가 불안정하다. 뷰어 관찰: 위를 보고 누운 시작은 한쪽 다리를
굽혀 일어나는 정형화된 동작, 엎드린 시작은 팔굽혀펴기 자세를 시도한다. 판정은 800 만 스텝에서 한다(성공·유지 스텝이 안 오르면
학습률/std 하한 조정 v4).

**성공 정의 재교정과 인계 측정 (v4).** 사용자 지적: 바닥 정책의 일은 높이에 도달하는 것이고 그다음은 서 있기 정책의 일이다.
앞의 "주저앉음" 검증은 성공 후에도 *바닥* 정책을 계속 돌린 것이라 인계 품질의 증거가 못 됐다. 직접 측정(느슨한 도달 조건: 머리 ≥ 0.9 m,
발 닿음, 기울기 < 60° 에서 서 있기 정책 v37 로 교체해 3 s, 시드 100개):

| 바닥 정책 | 도달 시드 | 인계 시 몸통 평균 | 3 s 뒤 몸통 ≥ 0.7 m | 3 s 뒤 직립 유지 |
|---|---|---|---|---|
| v2 (3.35 M) | 5/100 | 0.71 m | 1/5 | 1/5 |
| v3 | 18/100 | 0.73 m | 2/18 | 2/18 |

표본이 작다(2/18의 95 % 구간 약 1~35 %). 그래도 v37이 한 번도 연습하지 않은 상태에서 일부를 받아낸다는 점과, 약한 고리가 인계 이후의
균형이라는 점이 다시 확인됐다. 그래서 v4는 성공을 "도달"(몸통 ≥ 0.6 m, 머리 ≥ 0.9 m, 발 닿음, 기울기 < 60°, 유지 조건 없음)로 되돌렸다

**표준편차.** 바닥 정책의 행동 std 는 전 관절 0.57~0.68(서 있기 0.44~0.57)이고 결정적 행동의 65 %가 |a| > 0.9 로 포화돼 있다 -- 이 몸으로 일어나려면
큰 토크의 큰 동작이 필요하다는 뜻이고, std 가 커진 것을 곧바로 학습 불안정으로 읽으면 안 된다. 상한 클램프(0.6)가 계속 작동 중이라 풀어 보는

합친 시스템의 harsh 게이트. 서 있기 정책(v37)은 깊이 누운 시작이 필요 없어지면 재설계 대상이다.

받아냄은 5~9 %(오차 안)이라 체크포인트 선택 기준은 calm 게이트가 됐고, 퇴보 직전인 **v37 @96 M** 을 골랐다. 끝에서 끝까지(바닥 최종 + 서 있기 3 s, 100시드):
v37 @99 M 8/100, @120 M 3/100 (단일 정책은 0/160).

**v38 (서 있기, 인계 상태에서 시작).** v37 @96 M 에서 이어받고 `--handoff-pool handoff_pool_v4.npz --handoff-frac 0.4`: 풀은 바닥 v4 최종이 만든 1,500개
(시드 1000번대, 절반은 확률적 행동, 평가용 150개와 시드 분리), 나머지 시작은 calm 80 %, 버스트·보관소·머리 신기록·상관 노이즈·엔트로피 보너스(`--ent-coef 0.0`) 모두 끔.

풀은 **고정**이다(동적 갱신 없음): 평가용 150개와의 격차가 벌어지면(외움) 실패한 인계 상태 재생을 추가한다. 실수: 인계 풀 콜백에 `_on_step` 을 빠뜨려 첫 시도가
시작 직후 죽었다(손실 없음, 즉시 수정).

### 3.17 서 있기 영역 목표, 엎드린 정책 분리, 문턱 단계 조이기 (2026-10-13 ~ 10-15)

3.16의 결론("바닥 정책은 더 이상 병목이 아니다")은 느슨한 도달 조건(머리 ≥ 0.9 m)에서의 말이었고, 서 있기 정책은 그 상태를 5~9 %만 받아냈다.
이후 사흘은 (a) 도달 조건을 "서 있기 정책이 버티는 영역"으로 옮기고, (b) 시작 자세의 한쪽(엎드림 추정)이 전혀 안 풀리는 것을 풀고, (c) 구조를 측정으로 비교했다.
수치는 모두 **결정적 정책, 고정 시드, 서 있기 모델 v37 @96 M이 3 s(150스텝) 이어받아 몸통이 한 번도 0.7 m 아래로 안 내려가면 "버팀"** 기준이다.

**(a) 서 있기 영역 목표 (`FloorEnv(standready=True)`).** 도달 = 발 닿음 + 몸통 ≥ 1.08 m + 양 무릎 > -20° + |기울기| < 20° + |수직 속도| < 1 m/s + |기울기 속도| < 100°/s.
이 영역은 서 있기 정책이 직립 시작에서 92 %, 수직·회전 속도를 조금 더 얹어도 53~100 % 버티는 범위로 정했다(`analysis/stand_velocity_map.py`: 기울기 속도 ±200°/s에서는 33~43 %,
수직 속도만 1.5 m/s까지는 97~100 %). 결과: 느슨한 목표로 학습한 v4 계열은 영역에 2 %만 닿았고, 영역 목표로 바꾸자(v6~v8) 누운 시작 도달이 2 % → 32 %로 올랐다가 정체했다.
정체 진단(`analysis/floor_stuck_diag.py`, v8 @94.3 M, 200시드): 조건 하나하나는 대부분 만족하는데(무릎 99~100 %, 몸통 43/66 %, 기울기 70/96 %) **동시에** 안 맞는다(실패 137개 중 조건 하나만 모자란 것은 4개).
몸통 최고 높이 중앙값 0.84 m, 누운 실패의 74 %는 최고점에서 발이 바닥에 없다(던져 올리는 패턴). 공중 비율(몸통 > 0.6 m인데 발 없음)은 v4 67 % → v6 52 % → v7 45 % → v8 47 % → v9 46 %.
v9부터 시작을 누운 쪽만으로 했다(웅크린 시작은 서 있기 정책 몫으로 미룸).

**(b) 높이 × 속도 감점은 감속 습관을 만들지 못했다 (v10/v11/v12).** 몸통 0.6 m에서 0, 1.08 m에서 1이 되는 높이 가중치 × (0.25 |수직 속도| + |기울기 속도|/100°/s), 계수 0.08.
감속 지표(`analysis/speed_profile.py`): 몸통 1.0 m 이상 스텝 중 |기울기 속도| < 100°/s 비율이 v9 53 % → v12 @101.5 M 54 %(변화 없음). 도달은 34 → 36/100으로 해롭지는 않았다.
감점은 에피소드당 -2.5 ~ -5로 성공 보너스(+20)·머리 신기록(+6)보다 작아 정책이 그냥 흡수한 것으로 보이지만, 이 원인은 확인한 것이 아니라 추정이다.
처음부터 학습하는 엎드린 정책에 같은 감점을 같이 넣은 것(prone1~2)은 검증 없이 쓴 조합이었다(아래 (e)).

**(c) 환경 규칙 하나가 시간 제한을 가렸다.** `env.py`는 몸통이 `FALL_HEIGHT` 아래인 상태가 `DOWN_RECOVERY_STEPS`(250스텝 = 5 s) 연속이면 KO로 에피소드를 끊는다. 바닥 정책이 5 s 안에 한 번도 못 일어서면
450스텝 제한은 의미가 없었고, 뷰어 로그의 "250 steps" 에피소드로 발견했다. `FloorEnv(down_timeout=False)`(또는 `STANDAI_FLOOR_NO_DOWN_TIMEOUT=1`)로 끌 수 있고 2026-10-14 이후 바닥 정책 학습·측정은 모두 끈 것이다.
같은 v11 @98.8 M 정책: 제한 300 → 450 → 750스텝에서 도달 31 → 39 → 42, 버팀 16 → 20 → 22 (100시드, 5 s 규칙 있음, `analysis/time_limit_probe.py`). 450스텝으로 학습한 v12 vs 300스텝으로 학습한 v9(200시드, 450스텝 평가):
도달 82 vs 70, 버팀 41 vs 34. 같은 정책에서 5 s 규칙만 끄면 도달 82 → 88, 버팀 41 → 45(200시드). **효과는 작고 같은 방향이며 표본 오차(±5) 경계다.**

**(d) 시작 기울기 부호의 비대칭과 엎드린 쪽의 물리적 가능성.** 자연 분포에서 기울기 > 0이 159/200, ≤ 0이 41/200이다. 기울기 > 0은 몸통 +91°에 머리가 몸통보다 -x 쪽(위를 보고 누움으로 추정),
≤ 0은 -103°에 머리가 +x 쪽(엎드림으로 추정)이다. **"몸이 +x를 본다"는 가정에 기댄 해석이고 직접 검증하지 않았다.** `a_waist`의 +방향은 머리를 몸통 뒤(-x)로 보낸다(허리 +45°에서 머리-몸통 x가 -0.131 m, 0°에서 +0.032 m).
v12는 > 0쪽 87/159(55 %), ≤ 0쪽 1/41(2 %). MPC(예측 샘플링, 진단용)는 예전 6시드 중 엎드림이 1개뿐이어서 증거가 못 됐고, 엎드린 시작 6개(시드 100, 101, 111, 124, 135, 150)로 다시 돌린 결과
**5/6이 선다**(서 있던 비율 88~100 %, 첫 직립 21~30스텝 = 0.4~0.6 s, 시드 100만 쓰러짐). 기록된 행동을 열린 루프로 재생하면 3/6만 재현됐다(닫힌 루프라 정상). 몸의 한계가 아니라 학습의 문제였다.

**(f) 인계 상태 분석: 무엇이 버팀을 가르는가** (prone4 @41 M, 도달 163/400 중 버팀 61, 37 %). 영역 정의의 6개 변수(몸통 높이·무릎·기울기·수직 속도·기울기 속도·허리)는 버팀/못 버팀 분포가 겹친다.
추가 변수의 AUC(0.5 = 정보 없음, `analysis/handoff_auc.py`; 평균 비교는 `analysis/handoff_features.py`): **무게중심 x − 앞발 x 0.26**(버팀 +0.02 m, 못 버팀 +0.10 m), 무게중심 − 두 발 평균 0.34, 기울기 0.61, 발 간격 0.60, 수직 속도 0.59, 허리 0.44(버팀 13°, 못 버팀 22°), 나머지 0.47~0.58.
못 버티는 상태는 무게중심이 앞발보다 10 cm 앞에 있다. 영역에 이 조건(`com_max`)을 얹고 학습 전 정책에 적용하면 도달 중 버팀 비율이 38 % → 50 %(≤ 0.10 m) → 56 %(≤ 0.06 m) → 49 %(≤ 0.03 m)로 오르지만 도달 수가 줄어 버팀 총수는 오르지 않는다(80/30 → 54/27 → 43/24 → 35/17, 200시드).

가장 높이 올라간 순간의 허리는 중앙값 +46°(한계 +45°)로 거의 항상 한계에 붙는다(몸통 ≥ 0.9 m인 63개 중 뒤로 기움 27, 앞으로 기움 9, 곧음 27이 모두 같은 허리 각도). 무릎 중앙값은 -109°.
허리 조건을 영역에 넣자는 제안은 이 데이터(AUC 0.44, 방향도 반대)와 맞지 않아 철회했다. 몸통이 뒤로 기운 경우는 기울기 < 20° 조건으로 이미 걸러진다.

**결론:** 일어나기 모델 두 개만 쓰는 구조는 안 맞고(4 %), 순환은 이득이 없다(24 vs 26 %). 현재 최선은 C이고 끝에서 끝까지 서 있기는 약 26 %다. 병목은 서 있기 모델이 인계 상태를 받는 단계다
(도달 중 버팀 누운 쪽 51 %, 엎드린 쪽 36 %, 직립 시작은 77~92 %).

근거: v37은 이어받기 4번째이고 100 M 뒤 퇴보가 있었으며, 처음부터 학습한 선례 v21이 8.65 M에 5/100, 17.7 M에 15/100, 53~55 M에 직립 시작 게이트 30~40 %에 닿았다(11절 기록 `docs/stand_only_track.md` 11.18~11.19).
v37 @96 M은 대조군·대체물로 보존한다. 이 문서 작성 시점에 풀 생성은 진행 중이고 학습은 시작 전이다.

**v38 결과 (2026-10-12 종료, 136 M).** 40 M 스텝 예산을 다 쓰고 끝났다. 알림의 calm 게이트(30시드)는 0.37~0.53, 느슨한 인계 평가 150개 받아내기는 **8/150으로 v37 @96 M의 11/150보다 낮다**
(인계 풀 40 %를 섞어 학습했는데도 효과가 없었다). 풀이 느슨한 도달 조건(깊은 스쿼트)의 상태였던 것이 원인일 수 있으나 확인한 것은 아니다. 그래서 서 있기 정책은 위 (h)의 "엄격 영역 인계 풀 + 처음부터"로 간다.

### 3.18 서 있기 모델을 처음부터 / 인계 풀 / 룰 기반 컨트롤러 (2026-10-15 ~ 10-17)

3.17의 병목(서 있기 모델이 인계 상태를 받는 단계)을 풀려고 세 갈래를 시도했고, 모두 막혔다. 수치는 결정적 정책, 고정 시드 기준이다.

**인계 평가 도구.** 엄격 영역 인계 상태 풀 8,000개(엎드린 정책 prone8 86.5 M·97.8 M 각 2,000, 누운 정책 v12 101.5 M·102.65 M 각 2,000; 시드 1000·20000번대, `scripts/make_strict_pool.py`,
`checkpoints/pool_strict_all.npz`)와 학습에 안 쓰는 평가 세트 300개(엎드림 150 + 누움 150, 시드 0번대, 결정적; `checkpoints/eval_strict_all.npz`).
알림 `handoff_catch`의 기준(몸통 ≥ 0.7 m, 머리 ≥ 0.9 m, 기울기 < 40°를 20스텝 유지)으로 **v37 @96 M = 127/300 (42 %)**가 기준선이다.

**(a) 서 있기 모델을 처음부터: 전부 실패.** 직립 시작 게이트(고정 시드) 기준:

| 실행 | 몸 | 회복 게이트 | 풀 | 스텝 | 결과 |
|---|---|---|---|---|---|
| v39 | 1.5배 | 켬 | 40 % (처음부터) | 50 M | 게이트 0. 직립 시작에서도 바닥에 눕는다 (직립 시작 60개: 3 s 뒤 몸통 중앙값 0.40 m, 기울기 108°, 0/60·인계 0/300) |
| v40 | 1.5배 | 켬 | 없음 | 13 M | 0 (같은 붕괴) |
| v43 | 1.5배 | 켬 | 성능 게이트(직립 게이트 ≥ 10 %일 때 +0.025) | 55 M | 0. 풀 게이트 111번 모두 0.000이라 풀은 한 번도 안 들어옴 |
| v45 | 1.5배 | 끔(`STANDAI_NO_RECOVERY_GATE=1`, v21 시대 보상) | 없음, std 상한 0.4(`--std-max`) | 50 M | 0 (17 M 이후 12번 모두 0, `r_torso_upright` ~10, std 0.18로 굳음) |
| **v46** | **1배** | **끔** | 없음 | 4 M에서 일시정지 | **v21 재현 대조군, 판정 안 남** (v21은 8.65 M에 5/100) |
| **v48** | 1.5배 | 끔 | 없음, std 상한 0.4, **무릎 한계 없음**(`--no-knee-floor`) | 진행 중 | **처음으로 게이트가 오름** (3.19절) |

**학습 로그와 게이트가 어긋난 이유.** v43 @55.7 M에서 학습 로그 fall_rate는 0.39~0.49, 에피소드 길이는 650~900인데 게이트는 0이었다. 학습과 같은 방식의 벡터 환경에서 단계별로 재면
(16 에피소드) KO(몸통이 0.7 m 아래로 250스텝 연속)가 **아무 설정 없음 16/16, 학습 때의 무릎 각도 한계 -78°를 걸면 10/16(길이 569), 학습 설정 전부 10/16(595)**으로 로그가 재현된다.
무릎 한계는 직립 시작 에피소드에서 무릎 각도를 강제로 고정하는 장치(`KneeScaffoldCallback`, -50° → -80°)라 정책이 그 한계에 기대어 낮게 웅크린 채 버티는 법을 배운다(문서 11.13의 "낮은 안정 평형"과 같은 현상).
무릎 한계를 걸고 3 s 게이트로 재도 0/60이다. **fall_rate는 이 받침대 때문에 낙상을 실제보다 낮게 보고하고, 커리큘럼 게이트(fall ≤ 0.65 + 서 있기 ≥ 350)가 일찍 열려 쓰러진 시작이 일찍 섞인다.**

**기어 1.5배가 서 있기를 지우지는 않는다.** v21 @82.4 M(1배에서 학습)의 직립 시작 게이트를 현재 코드에서 기어만 바꿔 재면 1배 33, 1.25배 40, 1.5배 39/100이다
(문서의 기록 33 / 43과 일치: 환경 코드는 v21 수치를 재현한다). 즉 처음부터 1.5배로 학습하면 못 배우는 문제이고, 학습된 정책은 기어 변화에 견딘다. 스캐폴드의 코드 확인에서 젝·노력 페널티는 stand-only 보상에 안 들어간다
(기어 정규화 대상 아님). 바닥 정책과의 접점(몸·관찰값·행동 의미)은 보상·탐색 조정으로는 안 바뀐다.

**(b) v37에서 인계 풀로 이어 학습: 받아내기 안 오름.**
- v38(느슨한 풀 40 %, 136 M): 느슨한 인계 세트 8/150 (v37 @96 M은 11/150).
- **v47**(v37 @96 M + 엄격 풀 40 % + 실패 가중 재생 + `--std-min 0.45 --ent-coef 0.002` + 무릎·보조 스캐폴드 완료 상태 유지): 엄격 평가 세트 받아내기 +4 M에 128, +10 M에 **127/300**(기준선 127).
  풀 상태에 대한 통과율은 26 → 36 %로 오르는데(300개 구간 단위) 학습에 안 쓴 평가 세트는 안 올라서, 풀 상태를 외우고 일반화는 안 된다. 직립 시작 게이트(30시드)는 0.43 → 0.5로 유지.
- 새 학습 옵션: `--handoff-ramp-start/--handoff-ramp-steps`(풀 비율 선형 증가), `--handoff-gate-calm/--handoff-gate-step/--handoff-gate-every`(직립 게이트가 기준 이상일 때만 증가), `--handoff-fail-weight/--handoff-fail-every`(못 받은 상태 반복), `--std-max`.

**(c) 인계 시점·트리거 조정: 이득 없음.**
- 시점 오라클(`analysis/handoff_timing_oracle.py`, 120시작): 영역 진입 20스텝 전~100스텝 뒤를 5스텝마다 "여기서 넘기면 3 s 버티나"로 시험하면 도달한 것 중 "하나라도 되는 순간"이 엎드림 85 %, 누움 81 %지만
  이는 여러 번 시험한 선택 효과다(시점마다 38~56 %). 시점별 버팀: 누운 정책은 0~+60스텝에서 45~56 %로 평평하고 진입(0)이 최고 56 %, 엎드린 정책은 -5스텝이 50 %로 최고이고 진입 38 %, +5 이후 16 → 7 → 0~10 %로 급락.
- 트리거 단계 스윕(영역 엄격함 1.0 → 0.6, 시드 200): 도달은 엎드림 63 → 79 %, 누움 44 → 58 %로 늘지만 **버팀 총수는 22 %(엎드림 20~22 %, 누움 18~22 %)에서 변하지 않는다.** 늘어난 도달은 전부 서 있기가 못 받는 상태.

**(d) 룰 기반 컨트롤러.** `scripts/controller.py`(`GetUpController`): 낮은 동안 기울기 부호로 바닥 정책 선택(양수 누움, 0 이하 엎드림), 영역 진입 시 서 있기로 인계, 쓰러지면 다시 바닥 정책(옵션). 평가 `analysis/controller_eval.py`
(자연 분포 시작 200, 20 s, 몸통 ≥ 0.95 m·기울기 < 30°를 마지막 25스텝): **복귀 있음 24 % (누운 쪽 37/159, 엎드린 쪽 12/41), 복귀 없음 18 %**, 인계 58 %, 서 있기 쓰러짐 121회.
이전 측정(24 vs 26 %)과 복귀의 효과 방향이 반대라 표본 오차(±6) 안이다. 룰 컨트롤러 기준선 = 약 24 %.

**결론.** 병목은 변하지 않았다: 도달한 상태 중 서 있기 모델이 받는 것은 약 42 %(누움 51 %, 엎드림 36 %)이고, 이어받기·풀 학습·실패 가중·탐색 유지·인계 시점·트리거 완화 어느 것으로도 움직이지 않았다.
처음부터 학습하는 길은 무릎 한계를 끈 v48 전까지 열리지 않았다(3.19절; v46은 판정 보류). 못 받는 상태는 무게중심이 앞발보다 약 10 cm 앞에 있는 자세(AUC 0.26)라 한 발 내딛는 동작이 필요해 보이지만 확인한 것은 아니다.

### 3.19 무릎 한계(받침대)를 빼면 처음부터 학습이 오르기 시작한다 + 벤치마크 (2026-10-17)

**무릎 한계가 실제로 무엇인지.** `KneeScaffoldCallback`이 직립 시작(calm) 에피소드에서만 매 스텝 무릎 `qpos`를 한계(-50° → -80°)로 되돌려 놓는다(위치 강제, 힘이 아님). 몸 모델의 실제 무릎 범위는 -140°이고(관절 정의 -2.44 rad),
사람의 무릎 굽힘은 대략 135~150°로 알고 있다(문헌 확인 안 함). 즉 한계는 모델 범위의 80/140이고 반쯤 앉은 자세에서 멈추는 **인공적인 제한**이다. 문서 11.15는 이를 "해부학적 제약"으로 분류해 영구 유지하기로 했는데 숫자로는 맞지 않는다.
생긴 이유는 코드 주석(10.37): 서 있는 상태로 시작해도 1초 안에 무릎을 -136° 부근의 깊은 웅크림으로 되돌아가서, 보상으로 설득하는 시도(10.34, 10.35)가 계속 실패해 "도망갈 구멍을 막았다". 사용자의 가설: 1배 몸은 힘이 약해 깊이 굽힌 뒤 못 일어나서 이 장치가 필요했고
(MPC가 1배에서 누운 시작 6개 중 2개, 1.5배에서 5개를 일으킨 것과 방향이 맞다), 1.5배 몸에서는 필요 없거나 오히려 부작용이 크다. **이 가설은 힘 부족이 원인이라는 직접 실험 없이 주석과 MPC로 뒷받침되는 해석이다.**
평가·인계·컨트롤러는 한계 없이 돌고(`watch_locomotion.py`만 기본 -80°를 건다), 학습만 걸려서 정책이 한계에 기대는 불일치가 있었다.

**v48: 같은 설정에서 한계만 뺀 실행.** 1.5배 몸, 회복 게이트 끔(`STANDAI_NO_RECOVERY_GATE=1`), std 상한 0.4, 풀 없음, `--no-knee-floor`(KneeScaffoldCallback을 달지 않음). 이전 6번(v39~v45, 한계 있음)은 55 M 스텝까지 게이트 0이었다.
알림 게이트(고정 시드, 결정적, 직립 시작은 30시드):

| 스텝 | 전체 게이트 | 직립 시작 게이트 | 비고 |
|---|---|---|---|
| 2.5 M | 0 | 0 | |
| 5.0 M | 0.10 | 0.17 | 처음 오름 (연속 지표: 처음 쓰러지는 시점 28 → 84스텝, KO 20/20 → 13/20) |
| 7.1 M | 0.20 | 0.30 | |
| 9.9 M | 0.27 | 0.47 | |
| 12.4 M / 14.4 M / 16.5 M | 0.20 / 0.23 / 0.20 | 0.37 / 0.47 / 0.37 | 10 M 이후 평평 (30시드라 ±9 노이즈) |

**벤치마크 (`scripts/analysis/benchmark.py`).** 한 명령으로 서 있기 모델의 인계 받아내기(평가 세트 300), 직립 시작 게이트와 무릎 구간별 성공, 바닥 정책 두 개의 도달·버팀, 룰 컨트롤러 끝에서 끝까지를 표 하나로 출력하고
`checkpoints/analysis/benchmark_<tag>.json`에 저장한다(기본 4 min, 시드 200). 기준선(v37 @96 M + v12 + prone8)과 v48 @16.8 M:

| 항목 | v37 @96 M (기준선) | **v48 @16.8 M** |
|---|---|---|
| 인계 상태 300개 받아내기 (진짜 직립) | **127 (42 %)** | 88 (29 %) |
| 직립 시작 게이트 (100시드) | **51** | 41 |
| 무릎 ≥ -10° / -25~-10° / -40~-25° / < -40° | **90 / 68 / 43 / 23 %** | 71 / 54 / 40 / 16 % |
| 누운 정책 → 서 있기가 3 s 버팀 (시작 대비) | **28 %** | 19 % |
| 엎드린 정책 → 서 있기가 3 s 버팀 | **22 %** | 12 % |
| 룰 컨트롤러 끝에서 끝까지 (20 s) | **24 %** | 20 % |

v48은 아직 모든 항목에서 v37보다 낮다. 알림의 30시드 직립 게이트(0.37~0.47)만 보면 v37(약 50)에 근접한 것처럼 읽혔지만 100시드·인계·웅크린 시작으로 보면 격차가 크다. 단 v37은 96 M 스텝, v48은 16.8 M 스텝이고 v21은 17.7 M에 15/100이었다.
**판독 방식:** v48 체크포인트를 약 10 M 스텝마다 벤치마크로 재서 v37과 비교하고, 인계 받아내기가 127을 언제 넘는지를 본다. 넘으면 서 있기 모델 교체, 정체하면 v47과 같은 벽.

**부수 확인.** 조정한 파라미터가 바닥 정책과 충돌하는지: 바닥 정책과의 접점은 몸(기어), 관찰값(70차원), 행동 의미뿐이고 보상·탐색(std, 풀 비율 등)은 서 있기 학습에만 쓰여 충돌하지 않는다(`FloorEnv`는 부모 보상을 버린다).
기어 1.5배 + 젝·노력 페널티 정규화 제안은 stand-only 보상에 이 항들이 없어 무효였다. 새 옵션: `train_locomotion.py --no-knee-floor`, `train_floor.py --supine-frac`(누운 시작만; 누운 정책을 엎드린 정책의 방식으로 다시 학습하는 시험용, 아직 안 돌림).

**실수.** (1) 알림의 30시드 게이트를 "v37에 근접"으로 보고했다가 벤치마크로 뒤집혔다. 표본이 작은 알림은 방향 확인용이고 판정은 벤치마크로 한다. (2) 한계의 역사를 사용자의 설명을 거꾸로 이해해서 답했다("1배에서 받침대 전략이 통했다" vs 올바른 이해 "1배의 약한 몸 때문에 받침대를 만들었다").
(3) 이어서 해 본 시도들의 판독 지점을 지난 뒤에 보고한 적이 있다(v45).

### 3.20 학습률을 낮추면 서기 정책이 안정되고 20초 서기율이 29 -> 41 %로 오른다 + 시작 분포 80:20은 생성기의 부산물 (2026-10-18)

**v53 (처음부터, 시작 분포를 인계 상태에 맞춤).** v48과 같은 처음부터 설정(x1.5 몸, 이전 보상 `STANDAI_NO_RECOVERY_GATE=1`, `--no-knee-floor`, `--std-max 0.4`)에 시작 분포만 바꿨다:
harsh 시작에서 토르소 0.7 m 아래(누운 상태)를 다시 뽑고(`STANDAI_HARSH_MIN_TORSO=0.7`), 정상·harsh 시작의 60 %에 인계 풀의 앞방향 속도와 관절 속도 잡음을 얹고(`STANDAI_START_VEL_*`),
30 %를 인계 풀 두 상태의 혼합(`λ·A+(1-λ)·B`, λ~U(0.7,1), 자세·속도 모두, `STANDAI_MIX_*`)에서 시작했다. 풀은 `pool_big_all.npz` 32,000개(누운 정책 v12 두 체크포인트, 엎드린 정책 prone8 두 체크포인트, 각 8,000, 시드 100000+).
정상 시작은 이미 수직 속도(표준편차 0.9)와 기울기 속도(1.6 rad/s)가 인계 상태(0.5, 1.0)보다 컸고(시작 직전 낙하 구간에서 생김), 모자란 것은 앞방향 속도(-0.07 대 +0.68 m/s)와 관절 속도(|v| 1.6 대 3.6 rad/s)였다.
혼합 상태는 실제 인계 상태보다 쉽다(v37이 61 % 받아냄, 실제 48 %).

**v53 곡선과 불안정.** 인계 포착(600개 상태: 기존 300 + 새로 만든 독립 300, 시드 400+, `eval2_all.npz`)을 1M 스텝 간격으로 재면 v37이 260인데 v53은 10M **277**, 20M **291**, 25~55M 200~235(평균 약 215), 56M 이후 150~177로 내려갔다.
인접 체크포인트(25k 스텝 간격)만 비교해도 73~87(300개 기준 표준편차 4.4), 1M 스텝만 가도 90씩 달라진다(19M 199, 20M 291, 21M 220). 10M, 20M 체크포인트는 독립 세트에서도 v37을 넘었다(147, 154 대 133).
그러나 전체 벤치마크에서 20M은 3초 유지(누운쪽 41 %)는 높은데 컨트롤러 20초 서기는 14 %, 10M은 34 %로 체크포인트마다 크게 다르다.
원인: **기본 학습률 3e-4에서 `approx_kl` 0.08~0.1, `clip_fraction` ~0.5**(정상은 0.01~0.03 / 0.1~0.2). 20M 이후 학습 보상(`r_stand_streak`, `r_torso_upright` 등)과 낙상률은 평평한데 포착만 출렁인다.
서기 정책에는 학습률 옵션이 없어 한 번도 낮춘 적이 없었다(바닥 정책 prone8만 5e-5). `train_locomotion.py`에 `--learning-rate`, `--target-kl` 추가.

**v54 = v53 @10M + 학습률 5e-5** (같은 분포, 높이 보상 9->15를 4M에 걸쳐): `approx_kl` 0.012~0.015, `clip_fraction` 0.13~0.18, std 0.34 -> 0.27. 포착(600, 누운쪽+엎드린쪽)은 10.5M 250 -> 13.5M 291 -> 13.5~20M에는 270~291(평균 약 280)에서 옆으로 움직이고
인접 체크포인트 차이는 ±10 안이다(v53은 ±50). 3초 포착만 보면 45~48 %에서 정체지만, 실제 쓰는 지표는 올랐다. 컨트롤러 20초 서기(쪽별 200시드):

| | 누운쪽 | 엎드린쪽 | 50:50 평균 |
|---|---|---|---|
| v37 @96M | 28 % | 30 % | 29 % |
| v54 @17M | 40 % | 38 % | 39 % |
| **v54 @20.3M** | 42 % | 40 % | **41 %** |
| v54 @20.7M | 40 % | 42 % | 41 % |

v54 @20.3M 전체 벤치마크: 인계 받아내기 누운쪽 69 %(v37 53) / 엎드린쪽 26 %(v37 34), 50:50 48 %(43); 바닥 정책+서기 3초 유지 38 / 15 %(28 / 22); 정상 시작 게이트 46(51), 무릎 < -40° 19 %(23).
약점: 정상 시작 게이트와 엎드린쪽 받아내기는 v37보다 낮다. **서기 기준선을 `checkpoints/best_stand_v54.zip`(v54 @20.3M의 복사본)으로 교체**, 벤치마크 기본값도 바꿨다(v37은 `--stand`로 지정).
v54는 20.7M에서 종료(13.5M 이후 정체, std가 계속 줄어듦).

**교훈**: 이것은 PPO의 표준 운영(KL을 0.01~0.03으로 유지)이고 새 발견이 아니다. 이 프로젝트에서 서기 정책에 학습률을 낮추지 않았던 것이 놓친 부분이었다. 평가 지표가 학습 지표와 따로 출렁일 때는 체크포인트 하나로 비교하지 말고
인접 체크포인트로 분산을 재고 독립 평가 세트에서 재확인한다.

**시작 분포 80:20은 생성기의 부산물.** 누운 시작(토르소 < 0.5 m)의 80 %가 기울기 부호 > 0이고, 부호와 물리적 방향(몸통 앞면이 위/아래)은 1,500개 모두 일치한다(누운쪽 = 등을 대고, 머리가 -x). 비율의 출처는 무너진 자세의 목표 관절각이다:
엉덩이 가동 범위가 -20~+120°이고 목표를 범위의 0.6배에서 균일하게 뽑아 평균이 +30° 굽힘 쪽이라 뒤로 주저앉는다. 아래는 생성 코드를 복제해 요소를 바꾼 측정(각 800회, 누운 시작 300~358개):

| 조건 | 등을 대고 누운 비율 |
|---|---|
| 현재 | 80 % |
| 몸통 기울기 교란 제거 | 91 % |
| 엉덩이 목표 0 | 52 % |
| 엉덩이 목표 앞뒤 대칭 | 47 % |

현실의 넘어짐 방향 분포는 이 프로젝트에서 정한 적이 없다. 그래서 벤치마크는 **쪽별 수치와 50:50 평균**을 함께 출력하게 바꿨다(기존 "컨트롤러 24 %"는 80:20 가중). 생성기 자체는 기존 수치와의 비교를 위해 그대로 둔다.
서기 정책 입장에서는 엎드린쪽 인계 상태가 더 어렵다(v37 받아내기 누운쪽 50 % 대 엎드린쪽 36 %, 600개). 바닥 정책이 닿는 쪽은 엎드린쪽이 더 쉽다(63 % 대 56 %).

**그 밖에 한 것**
- 풀 학습 v50b(풀 32,000개 30 %, 속도 잡음, 이어 학습): 5.3M 스텝 후 포착 123/300, 시작점 127과 같음. std가 0.47 -> 0.59로 올랐다(`--std-max` 없이 엔트로피 보너스).

- 정책이 못 받은 인계 상태 80개에 예측 샘플링 MPC를 돌리면 70개(88 %)를 받아낸다(정책이 받은 상태 20개는 19개): 같은 몸으로 가능한 상태들이다(`analysis/mpc_handoff.py`). 데모 100개 상태는 `checkpoints/mpc_demos_a.npz`에 있다(사용하지 않음).

재현(v54): `STANDAI_NO_RECOVERY_GATE=1 STANDAI_HARSH_MIN_TORSO=0.7 STANDAI_START_VEL_POOL=../checkpoints/pool_big_all.npz STANDAI_START_VEL_PROB=0.6 STANDAI_START_VEL_JOINT=3.5 STANDAI_MIX_POOL=../checkpoints/pool_big_all.npz STANDAI_MIX_PROB=0.3 STANDAI_MIX_LAM_LO=0.7`

### 3.21 컨트롤러 인계 영역을 느슨하게(0.7) 하면 20초 서기율 41 -> 50 % (2026-10-18)

v54(서기) + v12(누운) + prone8(엎드린) 컨트롤러에서 인계 영역의 엄격도(`FloorEnv(level=…)`; 1.0 = 엄격 서기 준비 영역, 0.0 = 가장 느슨)만 바꾼 결과, 20초 뒤 서 있는 비율(쪽별 200시드, 50:50 평균):

| 영역 | 누운쪽 인계 / 서기 | 엎드린쪽 인계 / 서기 | 50:50 서기 |
|---|---|---|---|
| 1.00 | 60 % / 42 % | 76 % / 40 % | 41 % |
| 0.85 | 70 % / 46 % | 83 % / 48 % | 48 % |
| **0.70** | 78 % / 46 % | 87 % / 53 % | **50 %** |
| 0.55 | 82 % / 46 % | 92 % / 52 % | 49 % |

(100시드 첫 측정: 1.0 43 %, 0.7 53 %, 0.4 46 %, 0.0 39 %.) 0.85~0.55는 구분되지 않고 1.0과의 차이(7~9 %p)만 확실하다. 서기 정책이 v37이던 때는 영역을 느슨하게 해도 버팀 총수가 변하지 않았는데(3.18), 강해진 v54에서는 느슨한 영역에서도 받아낸다.
`benchmark.py --handover-level`(기본값을 1.0에서 0.7로 바꿈; 이전 숫자는 1.0으로 재현). 인계 시점을 상태별로 학습해 정하는 방법은 아직 시도 전이다.

**v12가 누운 시작에서 영역에 못 닿는 이유**(`analysis/floor_miss_classify.py`, 누운 시작 159개 중 87개 도달 55 %): 못 일어남(토르소 < 0.7 m) 14개(9 %); 일어나다 멈춤(0.7~1.08 m, 중앙값 0.88 m)과 1.08 m는 넘었으나 6개 조건 미달(발 23, 기울기 13, 기울기 속도 12, 무릎 5)이 나머지다(누운·엎드린 시작 합계 기준 59개, 24개).
같은 정책의 제한 스텝을 300 -> 450 -> 750으로 늘리면 도달 31 -> 39 -> 42 %였다.

**누운 바닥 정책 처음부터**: 낮은 학습률(supine2 1e-4, supine3 3e-5 + `--target-kl 0.03`)에서 몸을 일으키는 법을 배우지 못했다(머리 0.5 m 넘는 비율 12~32 %, 단계 0에서 못 벗어남). 원래 계보(v2 -> v4 -> v6)는 **기본 학습률 3e-4의 큰 업데이트로 먼저 일어서는 법을 배운 뒤** 목표를 조였다.
1단계(`ppo_floor_s4a`: 누운 시작만, 느슨한 목표, 기본 학습률, 5 M 스텝)는 머리 0.5 m 넘기 99 %, 성공 56 %(학습 로그)/44 %(결정적)까지 갔다. 2단계(`ppo_floor_s4b`: s4a에서 이어, 서기 준비 영역 + 단계적 목표 `--level-start 0.0`, 학습률 1e-4)는 진행 중이다.

### 3.22 누운 정책의 한 다리 든 인계, 서기 정책의 좌우 비대칭, 서기 가치 보상 시도 (2026-10-18 ~ 19)

**한 다리를 든 인계.** 서기 준비 영역은 "발 하나만 바닥"이면 되어서, 누운 정책(v12)은 **인계 상태의 100 %가 한 다리를 엉덩이 높이까지 든 자세**(엉덩이 120°, 두 발 높이 차이 중앙값 1.28 m)다. 엎드린 정책(prone8)은 95 %가 두 발 모두 바닥(중앙값 0.03 m).
v12의 왼쪽 다리를 든 상태를 서기 정책 v54가 73 % 받아내는데, **왼쪽과 오른쪽을 맞바꾸면 8~9 %**, 새로 학습한 누운 정책(s4d)의 인계(오른쪽 다리)는 4 %(맞바꾸면 58 %)였다. 서기 정책이 좌우 비대칭이라는 뜻이다.
**대칭 처리(`scripts/sym.py`, `STANDAI_SYM_STAND=1`)**: 몸의 좌우 팔다리는 같은 모양이므로 왼쪽/오른쪽 관절·속도·행동을 맞바꾼 상태는 같은 물리다. 서기 정책 자신의 critic으로 "원래 관측"과 "맞바꾼 관측" 중 값이 큰 쪽을 골라 행동하고 행동을 되돌린다(관측 70차원 중 어깨·팔꿈치·엉덩이·무릎·발목의
위치·속도 칸을 경험적으로 찾아 맞바꿈). v12 인계 150개: 원본 109 / 맞바꿈 109 (대칭 처리 후; 원래 정책은 109 / 14). 컨트롤러, 알림기, 벤치마크, 가치 보상이 이 스위치를 따른다.
`FloorEnv`에 선택 조건 `STANDAI_FEET_GAP=<m>`(두 발 높이 차이 <= 한계, 단계 0에서 1.6 m -> 단계 1에서 이 값; 서기 준비 영역과 1단계 "도달" 목표 모두): 기존 v12는 0/100, prone8은 70/100으로 만족.

**누운 정책을 새로 학습한 기록.** 원래 계보(v2 -> v4 -> v6)는 **기본 학습률 3e-4로 먼저 일어나는 법을 배운 뒤** 목표를 조였다.
- supine2(학습률 1e-4)/supine3(3e-5 + `--target-kl 0.03`)을 서기 준비 영역 + 단계 곡선으로 처음부터: 일어나는 법을 못 배움(머리 0.5 m 넘는 비율 12~32 %, 단계 0에서 못 벗어남). 학습률을 낮추는 것은 이미 배운 뒤 다듬는 도구다.
- s4a(1단계: 누운 시작만, 느슨한 목표(머리 0.9 m + 발), 기본 학습률, 5 M 스텝) -> 머리 0.5 m 넘기 99 %, 성공 56 %(로그)/44 %(결정적). 이 시점에 이미 인계의 35 %가 다리 든 자세(s4b 6 M에 57 %, s4c 18.9 M에 75 %로 굳음).
- s4c: 속도 벌점을 끈 채 학습(엎드린 정책 명령을 그대로 복사한 실수; v12 계보는 `--speed-pen 0.08 --speed-vz-w 0.25`를 썼다) -> 단계 0.95까지 갔지만 엄격 영역 도달 16 %, 서기 정책이 받음 0 %.
- s5(s4d에서 이어, 두 발 조건 + 속도 벌점 0.08): 단계 0.60에서 정체(학습 성공률 10 % 안팎), 게이트를 15 %로 낮춘 s5b도 0.65.
- **s6a(처음부터, 1단계에서부터 두 발 조건을 단계 곡선으로 조임): 3.8 M 스텝에 단계 1.0(한계 0.15 m) 도달, 도달 44 %, 다리 든 비율 0 %** -> 두 발 조건이 1단계에서는 학습을 막지 않는다. 다만 이 1단계(느슨한 목표) 인계 상태의 무게중심은 앞발보다 47 cm 뒤라 서기 정책이 8 %만 받는다(서 있는 자세 이전의 인계).

**컨트롤러 인계 시점에 무게중심 게이트(`GetUpController(com_gate, wait_steps)`)**: 효과 없음. 엎드린 시작 20초 서기(200시드): 규칙 없음 53 %, 게이트 0.0 m/25스텝 50 %, -0.02 m 52 %, -0.05 m 48 %(대기 50스텝은 45~48 %).
기다려도 바닥 정책이 무게중심을 되돌리지 못하고(대기 만료 10~32 %), 인계 자체가 줄었다(87 -> 78~83 %). 코드는 기본값 꺼짐으로 남김.

**엎드린 인계를 서기 정책이 못 받는 이유**: 무게중심이 앞발보다 앞에 있기 때문. 엎드린 인계 300개에서 v54가 받는 비율은 `무게중심 - 앞발 x`가 < -0.05 m에서 84 %, -0.05~0 46 %, 0~0.05 22 %, 0.05~0.10 10 %, 0.10~0.15 6 %, >= 0.15 0 %(AUC 0.08, 즉 이 특징 하나로 거의 구분).
몸통 높이·속도·기울기·무릎·발 높이 차이는 거의 같다. 누운 정책(한 다리 든 인계)은 관계가 **반대**(받침발 기준 무게중심이 발 앞일 때 71~89 %).
"키 - 무게중심 높이" x 머리 높이 같은 높이 기반 점수는 다리 든 자세를 구분하지만(0.51 대 0.71) 받음/못 받음은 못 가른다(AUC 0.4).
**서기 정책의 가치(critic) V(s)는 받음/못 받음을 AUC 0.95(엎드린 인계)/0.90(누운 인계)/0.94(합침)로 구분**한다(받은 상태 평균 V 1972, 못 받은 상태 926; 누운 인계 2273 대 1684).

**서기 가치 보상 시도(`STANDAI_STAND_VALUE_CKPT/COEF/BONUS/SYM`)**: 인계 성공 순간에 `10 x V_norm`(V를 500~2500에서 0~1로)을 얹고, 스텝당 `0.05 x clip((머리 - 0.9)/0.4) x V_norm`을 더함(대칭 가치, 메인 보상은 그대로).
- 엎드린 정책 pv1(prone8에서 이어, 학습률 5e-5): 11분(0.5 M 스텝) 동안 성공률 55~65 %로 변화 없음, 중단.
- 누운 정책 b3(s6a 3.8 M에서 이어, 두 발 조건 없음, 속도 벌점 없음, 학습률 1e-4, 대칭 가치): 단계 29.7 M에 1.0 도달, 학습 성공률 35 %. b2(속도 벌점 0.08)는 단계 0.60에서 정체였고 벌점을 끄자 풀렸다(속도 벌점이 단계 진행을 막음).
  **85.95 M 벤치마크(대칭 서기 정책 v54, 인계 영역 0.7): 누운 시작 영역(엄격) 도달 40 %(v12 56 %), 도달한 것 중 서기 정책이 받음 28 %(v12 66~69 %), 시작부터 3초 유지 11 %(38 %), 컨트롤러 20초 서기 10 %(v12 조합 46 %)**. 엎드린쪽 44 %는 prone8 그대로.

### 3.23 서기 쪽에서 엎드린 인계를 받아내기: 무게중심 사다리 + 좌우 반전 + 내딛기 보상 (2026-10-19)

배경: 엎드린 인계를 서기 정책이 받는 비율은 23~30 %이고 원인은 무게중심이 앞발보다 앞에 있기 때문이다(3.22). "바닥 정책은 보내기만 하고 균형은 서기가 잡는다"는 구도를 지키려고 서기 쪽에서 풀어 봤다.

구현(모두 opt-in): `train_locomotion.py --com-ladder --ladder-first-index 16000 [--ladder-gate/-start/-every/-step/--ladder-no-mirror]`(`ComLadderPoolCallback`: 풀의 엎드린 절반을 `무게중심 - 앞발 x`로 줄 세워 쉬운 쪽 30 %부터 제시, 500k 스텝마다 허용 구간의 가장 어려운 1/4에서 3초 유지 통과율을 재서 게이트 이상이면 10 % 확대, 좌우 반전 사본 추가), 환경변수 `STANDAI_STEP_K`(퍼텐셜 보상 `K*(0.99*phi_t - phi_{t-1})`, `phi = -min(|COM x - 발 중점 x|, 0.3)`, 몸통 >= `STANDAI_STEP_MIN_TORSO`(0.7) 이고 |pitch| < 40도일 때만 지급, 로그 키 `r_step`).
공통: v54 -> `--learning-rate 5e-5 --target-kl 0.03 --no-knee-floor --std-max 0.4`, 풀 비중 0.4, 정상 시작 유지(`STANDAI_NO_RECOVERY_GATE=1 STANDAI_HARSH_MIN_TORSO=0.7`).

- **v55a**(사다리 + 반전, 5.7M 스텝, @26.05M = `checkpoints/best_stand_v55a.zip`): 사다리가 레벨 0.2(COM-앞 +0.05 m)에서 막혔다(경계 통과율 0.15~0.26, 게이트 0.35). 벤치마크: 엎드린 포착 23 %(v54 26), 누운 68 %(69), 정상 시작 게이트 45(46), 컨트롤러 50:50 50 %(50). 회귀는 없고 개선도 없음.
- 진단(`analysis/step_diag.py`, 확률적 3초): 놓친 엎드린 인계에서도 82~99 %가 뒷발이 시작 앞발을 추월하고 발 이동 중앙값이 0.25~0.43 m. 내딛기 동작 자체는 나온다(성공한 것 중 COM-앞 0~+0.10 m에서 33~50 %가 추월). 단, 쓰러지며 끌려가는 것과 구분하지 못하는 지표.
- **v55b**(v55a @26.05M + `STANDAI_STEP_K=300`, 사다리 게이트 0.25, 30M 스텝, @56.05M = `checkpoints/best_stand_v55b.zip`; K=30은 스텝당 보상 규모에 비해 약해서 중단): 사다리는 레벨 0.5(+0.125 m)에서 멈춤, std 0.19. 벤치마크: 엎드린 포착 27 %, 누운 72 %, 전체 포착 148/300(50 %, v54 48), 정상 시작 게이트 48, 컨트롤러 20초 서기 **50:50 54 %**(누운 50 / 엎드린 59).
- 독립 평가 세트 `eval2_all`(`analysis/catch_by_com.py`, 결정적): 엎드린 포착 v54 26 % / v55a 21 % / **v55b 29 %**, 누운 73 / 69 / 74 %. COM-앞 구간별(엎드린): < -0.05 m 93 / 78 / 85 %, -0.05~0 48 / 36 / 52 %, 0~+0.05 7 / 7 / 13 %, +0.05~0.10 5 / 5 / **26 %**(19개 중 1 -> 5개), **+0.10 m 이상(64개) 전부 0 %**.

결론: 회귀 없이 조금 좋아졌지만 폭이 150개 기준 오차 안이다(컨트롤러 54 %도 100시드/쪽). 내딛기 보상이 겨냥한 +0.05~0.10 m 구간에서만 변화가 보이고, 엎드린 인계의 43 %인 +0.10 m 이상은 여전히 0 %다. 다음 후보: 같은 설정 연장, 처음부터(사다리·반전·내딛기 보상·대칭 모두 처음부터), 또는 별도 인계 정책(여러 걸음이 필요한 구간).


### 3.24 별도 인계(핸드오버) 정책: 엎드린 인계 포착 29 -> 87 %, 엎드린쪽 20초 서기 49 -> 70~74 % (2026-10-19)

"바닥 정책은 보내기만 하고 균형은 서기가 잡는다"는 구도에서 서기 정책 쪽 개선(3.23)이 오차 범위였으므로, 바닥 정책과 서기 정책 사이에 **별도 인계 정책**을 끼웠다. 서기 정책이 받는 상태(COM이 지지 구간 안, 몸통 >= 1.0 m, |pitch| < 25도, 느림)까지 몸을 옮기고 넘긴다.

## 5. 이 조사로 얻은 방법론적 교훈

1. 목적함수에 `torso z`만 쓰면 최적화기(CEM이든 RL이든)가 물구나무·공중 이탈을 찾는다. 높이는
   발 접촉 + 직립과 함께 평가해야 한다. (환경 `FALL_HEIGHT` 게이트와 학습 보상도 pitch를 안 봐서 같은
   구멍이 이론상 열려 있다. 아직 정책이 악용한 적은 없다.)
2. 직립 보상을 모든 시점에 곱하면 앉았다 일어서는 데 필요한 상체 숙임을 벌주어 앉은 높이에서 멈춘다.
3. "몸의 한계 vs 학습의 한계"는 오라클(MPC) + 기어 스윕으로 학습 없이 가를 수 있다.
4. 100개 시드 게이트는 노이즈가 커서(±5%p) 단일 체크포인트 비교가 위험하다. 시드를 늘리고 같은
   시드로 쌍 비교한다.
5. 재생·커리큘럼류의 내부 지표(재생 성공률 등)는 분포가 바뀌는 지표라 고정 기준 측정 없이 믿지 않는다.

## 6. 한계

- 모든 학습이 시드 1회다. 학습 시드 반복, 기준선, 절제 실험이 없다.
- MPC 결과는 시작 6개(n=6)다. 비율이 아니라 "존재 증명 + 경향"으로만 읽어야 한다.
- 2D 래그돌 하나(직접 만든 몸). 표준 벤치마크나 실제 로봇과의 비교가 없다.
- 기어 스윕은 정책이 1배 몸에서 학습된 점이 섞여 있다.
- 몸 사양(기어 1.5배) 변경은 링크 질량을 그대로 둔 채 토크 한계만 키운 것이다. 실제 하드웨어에서 같은 토크를
  같은 속도로 내려면 더 큰(무거운) 모터가 필요하므로 이 결과는 약간 낙관적이다. 보고할 때 "기어 1.5배"가 아니라
  "최대 관절 토크 한계 1.5배"로 쓴다.
- v28 결과는 학습 1회·약 3.4M 스텝 시점이다.

## 7. 실수와 교정 (재발 방지용으로 남김)

- **대조군을 잘못 골랐다.** v28의 이득("calm 41→52, 300시드 123→152")을 출발점인 v26과 비교했는데, v26은 replay
  커리큘럼 학습으로 같은 몸에서 v21(136/300)보다 낮았다. 올바른 대조군(v21 @1.5배 몸)과 비교하면 이득은 +16~18/300
  수준이다. harsh의 6~8/197도 대조군이 이미 6/197이었다. 비교는 항상 "같은 몸, 같은 조건의 가장 단순한 출발점"과 한다.

- `pkill -f`/`pgrep -f` 패턴이 명령 전체 텍스트에 들어 있어 **내 셸을 스스로 종료**시킨 적이 세 번 있었다.
  이후 PID를 직접 지정하거나 스크립트 파일로 실행한다.
- 재시작 때 `--calm-already-relaxed`를 빼서 `calm_frac`이 0.47→1.0으로 되돌아가는 바람에 harsh 노출이
  ~9M 스텝 줄었다(CLAUDE.md 재개 명령에 반영).
- CEM 결과를 "몸이 0.5~0.6m까지 올라간다"고 과장 해석했다. 실제로는 뒤집힘·공중이었다(3.5절).
- 환경 `reset`에 기어 복원 코드를 넣으면서 기어를 `reset` 전에 키우던 MPC 도구가 1배로 되돌아갔고,
  **1.5배 MPC 첫 실행이 사실상 1배로 돌았다**(1배 결과와 소수점까지 같아서 발견). 도구를 고쳐
  `reset`을 거쳐도 유지되게 했고 1.5배·2배를 다시 돌렸다. 정책 쪽 기어 평가는 환경 수정 전에
  끝나서 영향이 없었다.
- CLAUDE.md에 "병목은 토크가 아니다"가 낡은 채 남아 있던 것을 고쳤다.
- 바닥 정책의 첫 성공 정의(머리 ≥ 0.9 m 한 순간)를 "주저앉는 동작"이라고 판단한 근거가 **성공 후에도 바닥 정책을 계속 돌린 것**이었다. 인계 후에는 서 있기
  정책이 맡으므로 이는 인계 품질의 증거가 못 됐다. 사용자가 역할 분담(바닥 정책의 일은 도달, 그다음은 서 있기)을 짚어서 다시 측정했다 -- 인계 상태를 서 있기
  정책에 넘겨 3 s 본 결과가 3.16절의 표다. 그 사이 v3(20 스텝 유지 조건)는 도달 18 %인데 성공 0 %로 보이는 학습을 한동안 돌렸다.
- 엎드려 팔굽혀펴기 자세에서 정체할 것(지역 최적점)이라는 추정을 사실처럼 말했다. 머리 신기록 보상은 내려가도 깎지 않으므로 그 자세가 보상으로 막는 구조는
  아니었다 -- 측정 전에는 가설이라고 표시했어야 한다. 표준편차 증가를 학습 불안정으로 읽은 것도 성급했다(행동 65 %가 ±1 포화, 큰 동작이 필요한 과제).

- **감점이 엎드린 정책 정체의 원인이라고 말했다**(prone2의 후퇴를 보고). 감점 없는 prone3도 같은 모양으로 후퇴했으니 근거가 없었다. 가설은 가설이라고 표시했어야 한다.
- **처음부터 + 문턱 단계 조이기 + 무게중심(prone7)을 권해서 34 M 스텝(약 7시간)을 썼는데 단계가 한 번도 안 올랐다.** 조이기는 사전학습된 높이 능력 위에서만 작동했다
  (prone4). 처음부터 학습이 통한 건 서 있기 정책(v21)처럼 촘촘한 보상이 있는 경우였다.
- **구조 비교의 예상이 틀렸다.** 순환(쓰러지면 바닥 정책으로 복귀)이 가장 좋을 거라고 했지만 순환 24 %, 순환 없음 26 %로 같았다. 바닥 정책이 서 있기 모델이 쓰러진 자세에서
  못 일어서는 것으로 추정되지만 진단하지 않았다.
- **감시 스크립트가 200시드 도달 점수 최대치를 "최고 체크포인트"로 뽑았다.** 400시드로 다시 재니 정점 후보 다섯이 구분되지 않았다(86.5 M의 도달 61 %는 우연 몫이 크다).
  체크포인트 선택은 상위 몇 개를 같은 400시드로 재서 정하고, 구분이 안 되면 "구분되지 않음"으로 둔다.
- 서 있기 "버팀"의 판정 기준을 섞어 말해서 뷰어(마지막 시점에 서 있음)와 측정(한 번도 안 쓰러짐)이 어긋나 보였다. 바닥 정책 혼자의 값이 1 %(안 쓰러짐)와 55 %(3 s 시점)로 갈렸다.
  보고할 때 판정 기준을 항상 같이 쓴다.
- 허리 각도 조건을 데이터 없이 제안했다가 AUC 0.44(방향 반대)로 철회했다.
- 바닥 환경의 에피소드 길이를 450으로 늘려서 효과를 얘기할 때 환경이 5 s 연속 쓰러짐에 KO를 거는 규칙(`DOWN_RECOVERY_STEPS`)을 빼먹었다. 5 s 안에 한 번도 못 일어선 개체는 450스텝을 쓰지 못한다.
- 엎드린 쪽 MPC 가능성은 예전 6시드 중 엎드림이 1개뿐이라 그 결과로는 말할 수 없었다. 엎드림 6개로 새로 돌려서 5/6을 확인했다.
- 첫 `kill $(pgrep -f …)`가 셸을 같이 죽인 적이 또 한 번 있었다(PID 직접 지정으로 해결).

- **서 있기 처음부터 학습(v39)에서 "실패 원인이 풀 비율"이라고 먼저 짚었다.** 풀이 없는 v40·v43·v45도 똑같이 쓰러져서 틀린 가설이었고 약 10시간(v39 50 M 스텝)을 썼다. 원인 후보를 분리하는 대조군(풀 없음)을 맨 처음에 돌렸어야 했다.
- **학습 로그의 낙상률로 "쓰러지지 않고 버틴다"고 읽을 뻔했다.** 학습 때만 걸리는 무릎 각도 한계가 받침대 구실을 한다(3.18절). 고정 시드 게이트와 연속 지표(바닥에 있는 비율, 3 s 뒤 몸통 높이)로만 판단한다.
- **이미 돌고 있는 실행을 확인하지 않고 같은 학습을 중복으로 켰다.** 한 로그 파일에 두 실행이 섞여 쓰였다(바로 정리). 새 학습 전에 `ps`로 설정까지 확인한다.
- **인계 풀 합치기에 시스템 `python3`(numpy 없음)를 써서 풀 파일이 안 만들어졌고 학습이 곧바로 꺼졌다.** 알림도 평가 세트가 준비되면 켜겠다고 해놓고 놓쳐서 한동안 알림이 없었다.
- **시점 오라클의 85 %를 처음에 크게 읽었다.** 후보 11~17개 중 하나라도 되는 확률이라 선택 효과가 크고, 시점별 비율은 38~56 %였다. 다행히 같은 응답에서 이 한계를 적었고 오프셋별 표로 확인했다.
- 판독 기준(15 M 스텝)을 넘긴 v45를 50 M까지 두고 나서야 보고했다. 기준 시점을 지나면 그때 바로 말한다.

## 8. 몸 사양 결정(v28)과 열린 질문

**결정:** MPC에서 1.5배가 2배와 같은 성공(5/6)을 냈고, 정책도 1.5배 몸에서 정자세를 잃지 않으면서
웅크린 구간이 올랐으므로(115→140~149/300) 이후 기본 몸을 기어 1.5배로 한다
(`locomotion_env.BODY_GEAR_SCALE`, 환경변수 `STANDAI_BODY_GEAR`로 변경 가능, 공용 `build_model.py`는
건드리지 않음). **이 문서의 v28 이전 모든 수치는 1배 몸 기준**이고, 몸 사양이 다른 게이트 수치는 비교하지
않는다. 보고할 때는 "원래보다 50% 강한 몸"이라고 명시해야 한다. 출발 정책(v26 91.45M)의 새 몸 기준선은
calm 41 / full 22 / harsh 5 (1배 몸 37 / 18 / 6, 시드 100개).

질량 대비 최대 토크(제어 입력 최대치 기준, 몸 질량 66.1kg):

| 관절 | 1배 | 1.5배 |
|---|---|---|
| 엉덩이 | 180 Nm (2.7 Nm/kg) | 270 Nm (4.1) |
| 무릎 | 60 Nm (0.9) | 90 Nm (1.4) |
| 발목 | 40 Nm (0.6) | 60 Nm (0.9) |
| 허리 | 70 Nm (1.1) | 105 Nm (1.6) |

사람과의 비교는 기억에 의존한 대략값이라 여기에 적지 않는다. 관절별 스윕(3.5절)이 한 관절 그룹의 효과를
분리하지 못했으므로, 일괄 1.5배의 근거는 "전체를 키우면 MPC가 5/6, 정책이 calm에서 이득"이지 특정 관절의
부족이 아니다.

**v28 판단 기준:** 새 몸에서 (a) harsh-only가 4~7을 벗어나는지, (b) 300시드 표에서 -40°~-25° 구간이
출발 체크포인트 대비 오르는지, (c) 정자세(-10° 이상)가 유지되는지.


- (결정됨, 위) **몸을 영구히 키우는 선택지:** MPC에서 1.5배면 2배와 거의 같은 성공(5/6)이 나왔다. 이 프로젝트는 이미
  해부학 비교로 기어를 한 번 조정한 적이 있다(hip 90→180, ankle 14→40). 기어 1.5배를 기본 몸으로
  채택하면 커리큘럼이 필요 없어질 수 있다. 대신 "인체 비율에 맞춘 몸"이라는 전제와 어긋나는지가
  결정 사항이다.
- 대표 자세 사다리(웅크림/무릎 꿇기/앉기/눕기)는 아직 시도하지 않았다. 일어서기가 0.6~0.7m 시작에서만 되는 것이 근거다.
- MPC를 교사로 쓴 시연 모방은 순수 RL이 아니게 되므로 보류 중이다.
