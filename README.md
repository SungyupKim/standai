# standai

A 2D MuJoCo ragdoll biped that learns, with PPO (Stable-Baselines3), to get up from lying on its back or face down and stay standing. Split out of [`fightai`](../fightai), the combat self-play league this body was built for.

Details: [`docs/TECHNICAL_SUMMARY.md`](docs/TECHNICAL_SUMMARY.md) (English summary), [`docs/experiments_2026-10-11.md`](docs/experiments_2026-10-11.md) (Korean, every experiment with its failures), [`docs/stand_only_track.md`](docs/stand_only_track.md) (Korean, full history), [`CLAUDE.md`](CLAUDE.md) (working notes). Checkpoints: [huggingface.co/SungyupKim/standai-getup](https://huggingface.co/SungyupKim/standai-getup).

> ## Result: **~94%** of lying starts are standing 20 s later (0/160 at the start of the project)
>
> **One 512x512 network**, fresh seeds, 600 starts per side: **supine 97.7%, prone 90.7%, 50:50 average 94.2%**, against 70.8% for the rule-based controller of four PPO policies it was distilled from (docs 3.24 addendum 13-15). Checked for shortcuts: no unphysical `root_x`/`root_ry` force is applied, moving the parked opponent away changes nothing, pushes of 150-500 N after the get-up change nothing.
> Caveats: simulation only, 2D; starts come from the environment's own lying-start generator (other start poses untested); one training run per configuration; the 50:50 supine/prone mix is an assumption; +-2.5 points sampling error.

## How it was made

1. **Grow the pieces separately**, each with its own reward and curriculum (supine floor, prone floor, a hand-over policy for prone arrivals, stand policy), joined by a rule-based controller: 24% -> ~72% over several weeks (docs list every step and every failure).
2. **Distil the whole controller, switching rules included, into one network** with DAgger (`scripts/distill_controller.py`): 74.5% vs 73.8% for the rules.
3. **Fine-tune that network end to end** with PPO on a 20 s "standing" reward (`scripts/train_getup.py`, 40M steps): **94.2%**.

Network size barely matters (same recipe, 12M end-to-end steps, 50:50: 512x512 92%, 256x256 93%, 128x128 89%, 64x64 85% vs 72% for the rules). This is *not* evidence that one network trains from scratch: big networks trained from scratch on the floor task failed repeatedly, which is why the pieces come first. Things that did not move the rule-based system (reward stacking, re-training the stand policy, hand-over timing gates, supine hand-over policies, critic-based rewards) are in the docs.
Limits: ~1B steps in total (get-up papers use ~5B), limb torque x1.5 without scaling link masses. Much of the code and analysis was written in a pair-programming loop with Claude (an AI assistant); experiment design decisions and review were the repository owner's.

## Try it (1 minute, no checkpoints in git)

```bash
git clone https://github.com/SungyupKim/standai && cd standai
python -m venv .venv && .venv/bin/pip install mujoco gymnasium stable-baselines3 huggingface_hub pillow
.venv/bin/python scripts/demo_hf.py            # downloads the network from Hugging Face, runs 50 supine + 50 prone starts (~1.5 min)
.venv/bin/python scripts/demo_hf.py --video    # also writes demo_hf.mp4 / .gif (needs ffmpeg)
```
Expect about 95% (supine) and 87-91% (prone) standing after 20 s; small samples are noisy. Other measurements (paired against the rule-based controller on the same seeds; checkpoints from the Hugging Face repo):
```bash
env -u STANDAI_NO_RECOVERY_GATE .venv/bin/python -I scripts/analysis/getup_strict_eval.py --arms teacher <path to getup_e2e_512.zip> --seed0 99100 --n 200
```
Viewers need an OpenGL display (`DISPLAY=:1` here). A shell that exports training variables (`STANDAI_*`) contaminates measurements: pass them per command with `env VAR=... cmd` and measure with `env -u`.

## Layout

```
scripts/getup_env.py          GetUpEnv: the whole task as one 20 s environment; distill_controller.py, train_getup.py: distillation and PPO; demo_hf.py: quick start
scripts/controller.py         GetUpController: the rule-based combination of the four policies (the teacher / baseline)
scripts/floor_env.py, locomotion_env.py, handover_env.py   environments of the floor, stand and hand-over policies (train_floor.py, train_locomotion.py, train_handover.py)
scripts/analysis/             measurements and diagnostics behind the docs (benchmark, getup_strict_eval, funnel, ...)
scripts/*_notify.py, overnight_*.sh   unattended pipelines with KakaoTalk progress messages
docs/  models/  assets/       documentation, MJCF body (generated by build_model.py), demo video
```
`build_model.py`, `env.py`, `view.py` and `kakao_notify.py` are copies of [`fightai`](https://github.com/SungyupKim/fightai) files, not a shared dependency: a body change needs the same edit in both repos.

## Methodology

SB3's training-log metrics can move opposite to what matters, so every claim is re-measured deterministically on fixed seeds per start side, compared on the same seeds and given an error bar; the same seeds move +-4 points between runs, so differences below ~3 points need 600+ paired starts. Recorded evaluation mistakes (leaked environment variables, a hand-over policy applied to the wrong side, starts that were not lying down) are in `CLAUDE.md` and the docs.

## Roadmap

Standing from any posture -> walking (velocity tracking) -> transplant into fightai's combat action/observation space (`transplant_locomotion.py`, still in fightai).
